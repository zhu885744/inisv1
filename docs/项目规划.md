## 逻辑梳理
- 创建时间（CreateTime）：用户点击「创建文章」生成，终身不变
  ✅ 核心价值：记录文章的诞生时间，是数据的「原始身份标识」，代表内容的最初创建节点；
- 发布时间（PublishTime）：用户点击「发布文章」生成，首次发布后不变（支持自定义）
  ✅ 核心价值：记录内容对外展示的时间，是面向用户 / 运营的「业务时间」，代表内容正式上线的节点；
- 更新时间（UpdateTime）：每次编辑保存文章自动刷新，随内容变化而变
  ✅ 核心价值：记录内容的最新修改时间，是面向开发 / 运营的「维护时间」，代表内容的最新状态节点。

## 当前系统存在的问题
1. 注销流程存在事务与并发问题
app\api\controller\users.go
app\model\users.go
流程：destroy 先发验证码 → 验证 → 检查密码 → 更新密码为随机串 → 硬删除用户 → 异步清空关联数据。

风险：
若 Force().Delete 失败，密码已被修改且用户被软删除？实际代码是硬删除，但密码修改和删除不在一个事务，可能导致密码改后删除失败，用户无法登录且账户残留。
关联数据清空（文章、评论等）使用 go 异步执行，若失败无感知，且与主删除动作无事务保证，导致数据不一致。
异步 Destroy 内部又调用 go 多次，可能产生大量未完成协程。
