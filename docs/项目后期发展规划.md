# inis CMS 项目后期发展规划

## 一、项目现状分析

### 1.1 技术架构

| 层级 | 技术栈 | 说明 |
|------|--------|------|
| 后端框架 | Go 1.25 + Gin | RESTful API 服务 |
| 数据库 | MySQL + GORM | 自动迁移、软删除 |
| 缓存 | Redis / 文件 / 内存 | 三级缓存驱动 |
| 实时通信 | Gorilla WebSocket | 广播/单播/私聊/ACK 确认 |
| 存储 | 本地 / 阿里云 OSS / 腾讯云 COS / 七牛 Kodo | 多存储驱动 |
| 管理后台 | Vue 3 + Vite + Element Plus + Pinia | SPA 单页应用 |
| 前台主题 | 独立主题（纯 HTML/CSS/JS） | 通过 API 调用后端 |

### 1.2 已实现的核心功能

- **用户系统**：注册/登录/注销/JWT 认证/权限组/角色管理
- **内容管理**：文章/页面/动态/评论/标签/分类/友链/公告/轮播
- **互动系统**：点赞/收藏/关注（`UserLikes` / `UserCollects` / `UserFollows`）
- **经验等级**：经验值获取（`EXP` 表）+ 等级体系（`Level` 表，7 级：新手→大师）
- **实时通信**：WebSocket 连接管理、广播、私聊、离线消息、ACK 确认
- **安全防护**：QPS 限流、IP 黑白名单、API Key、敏感词过滤
- **文件管理**：附件上传/下载/删除，多存储驱动，上传频率限制
- **通知系统**：邮件/阿里云短信/腾讯云短信/Webhook 多驱动
- **搜索功能**：全局搜索/文章/用户/标签等多维度检索
- **配置管理**：Key-Value 动态配置（`Config` 表），支持 JSON 存储
- **国际化**：中/英/日/韩/俄五种语言

### 1.3 现有问题与待改进点

1. **注销流程存在事务问题**：密码修改和删除不在同一事务中，异步清理关联数据无失败感知
2. **管理后台前后端耦合**：Vue SPA 打包为静态资源，非 SSR 不利于 SEO 和首屏加载
3. **缺少用户激励体系**：经验值/等级已实现，但缺少积分、余额、勋章等完整激励闭环
4. **消息通知不完善**：WebSocket 有实时通信能力，但缺少站内消息通知的持久化和 UI 展示
5. **缺少社交登录**：目前仅支持账号密码注册

## 三、Phase 1：基础完善 —— 消息通知系统

### 3.1 目标

建立完整的站内消息通知体系，让用户能收到系统通知、互动提醒、私信等。

### 3.2 后端实现

#### 3.2.1 新增数据表 `notifications`

```go
// app/model/notification.go
type Notification struct {
    Id          int    `gorm:"type:int(32); comment:主键;" json:"id"`
    Uid         int    `gorm:"type:int(32); comment:接收用户ID; default:0;" json:"uid"`
    FromUid     int    `gorm:"type:int(32); comment:发送用户ID; default:0;" json:"from_uid"`
    Type        string `gorm:"size:32; comment:通知类型;" json:"type"`
    // 类型枚举: system(系统通知) / like(点赞) / collect(收藏) / follow(关注)
    //          / comment(评论) / reply(回复) / private(私信) / exp(经验) / badge(勋章)
    Title       string `gorm:"size:256; comment:标题;" json:"title"`
    Content     string `gorm:"type:text; comment:内容;" json:"content"`
    TargetType  string `gorm:"size:32; comment:关联目标类型;" json:"target_type"`
    TargetId    int    `gorm:"type:int(32); comment:关联目标ID; default:0;" json:"target_id"`
    IsRead      int    `gorm:"type:tinyint; default:0; comment:是否已读;" json:"is_read"`
    Status      int    `gorm:"type:tinyint; default:1; comment:状态;" json:"status"`
    // 公共字段
    Json        any    `gorm:"type:longtext; comment:JSON数据;" json:"json"`
    Text        any    `gorm:"type:longtext; comment:文本数据;" json:"text"`
    Result      any    `gorm:"type:varchar(256);" json:"result"`
    CreateTime  int64  `gorm:"autoCreateTime; comment:创建时间;" json:"create_time"`
    UpdateTime  int64  `gorm:"autoUpdateTime; comment:更新时间;" json:"update_time"`
    DeleteTime  soft_delete.DeletedAt `gorm:"comment:删除时间;" json:"delete_time"`
}
```

#### 3.2.2 通知触发点

在现有业务逻辑中嵌入通知创建：

| 触发场景 | 通知类型 | 触发位置 |
|----------|----------|----------|
| 用户点赞我的内容 | `like` | `UserLikes.Like()` 方法内 |
| 用户收藏我的内容 | `collect` | `UserCollects.Collect()` 方法内 |
| 用户关注我 | `follow` | `UserFollows.Follow()` 方法内 |
| 用户评论我的内容 | `comment` | 评论控制器 `create` 方法 |
| 用户回复我的评论 | `reply` | 评论控制器（pid != 0） |
| 经验值变动 | `exp` | `EXP.Add()` 方法内 |
| 系统公告 | `system` | 管理员后台手动触发 |
| 私信消息 | `private` | WebSocket 私聊持久化 |

#### 3.2.3 WebSocket 推送增强

- 通知创建后，通过 WebSocket 实时推送给在线用户
- 消息类型为 `"notification"`，前端收到后更新未读计数
- 私聊消息已通过 WebSocket 实现，需增加持久化到 `notifications` 表

#### 3.2.4 API 接口（遵循 15 个基础接口规范）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/notifications` | 获取通知列表（分页） |
| GET | `/api/notifications/{id}` | 获取单条通知 |
| GET | `/api/notifications/count` | 获取未读数量 |
| PUT | `/api/notifications/read` | 标记已读（支持 ids 批量） |
| PUT | `/api/notifications/read-all` | 全部标记已读 |
| DELETE | `/api/notifications` | 删除通知（ids） |

### 3.3 管理后台实现

在 `admin/src/views/admin/pages/` 下新增 `notifications.vue` 页面：

- 通知列表管理（发送系统通知、查看所有通知）
- 在导航栏 `nav.vue` 添加消息铃铛图标 + 未读红点计数
- 实时 WebSocket 接收新通知并更新计数

### 3.4 前台主题 API 接口

- 前台主题通过 `/api/notifications` 接口获取用户通知
- 需要携带 JWT Token 验证身份
- 支持分页、未读过滤、类型筛选

#### 4.1.2 积分获取规则

积分获取与经验值体系并行，使用 Config 表 `SYSTEM_INTEGRAL_RULES` 配置：

```json
{
  "sign_in":         {"name": "每日签到", "value": 10, "daily_limit": 1},
  "article_create":  {"name": "发布文章", "value": 20, "daily_limit": 5},
  "comment":         {"name": "发表评论", "value": 5,  "daily_limit": 20},
  "article_liked":   {"name": "内容获赞", "value": 5,  "daily_limit": 20},
  "article_collected":{"name": "内容被收藏", "value": 10, "daily_limit": 10}

```

#### 4.1.3 积分与经验值的关系

- 积分和经验值是两套独立体系
- 经验值 → 用户等级（不可消费）
- 积分 → 可消费货币（兑换/购买）
- 可选：积分可兑换为经验值，反之不可

#### 5.2.6 与原 Vue 管理后台的关系

- **过渡期**：SSR 管理后台与 Vue 管理后台并行运行
- **路由区分**：`/admin` 访问 SSR 版，`/admin-spa` 访问 Vue 版（或通过配置切换）
- **最终目标**：SSR 版完全替代 Vue 版，减少前端依赖和维护成本

### 5.3 优势分析

| 对比项 | Vue SPA（当前） | SSR 后台（规划） |
|--------|----------------|------------------|
| 构建工具 | 需要 Node.js + Vite | 无需构建 |
| 部署复杂度 | 需构建 dist + 配置 Nginx | 直接嵌入 Go 二进制 |
| 首屏加载 | 需加载 JS 后渲染 | 直接输出 HTML |
| SEO | 不支持 | 原生支持 |
| 依赖项 | 大量 npm 包 | 零外部依赖 |
| 维护成本 | 需维护前端项目 | 统一 Go 项目维护 |
| 开发效率 | 组件化开发快 | 模板复用稍慢 |
| 浏览器兼容 | 需 polyfill | 原生 HTML 兼容性好 |

## 九、风险与注意事项

### 9.1 技术风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 积分/余额并发安全 | 积分丢失或重复发放 | 使用数据库事务 + 行锁 |
| SSR 开发效率 | 开发速度慢于 SPA | 先做核心页面，逐步迁移 |
| 勋章检查性能 | 大量用户定时检查 | 使用事件驱动 + 增量检查 |
| WebSocket 消息丢失 | 通知未送达 | ACK 确认 + 离线消息队列 |

### 9.2 开发规范

- 所有新模块严格遵循 `二次开发规范.md` 中的 15 个基础接口标准
- 所有数据模型包含 `Json`、`Text`、`Result` 公共字段
- 所有数据模型实现 `AfterFind` 钩子和 `result()` 方法
- 积分/余额变动必须记录流水日志
- 通知创建必须异步，不阻塞主业务

## 十、总结

本规划基于 inis CMS 现有架构和功能，明确了四个阶段的发展方向：

1. **Phase 1** 补齐消息通知短板，建立完整的站内通知体系
2. **Phase 2** 构建用户激励闭环（积分 → 消费 → 勋章 → 成就），提升用户活跃度
3. **Phase 3** 将管理后台从 Vue SPA 改造为 SSR 纯 HTML/CSS/JS，降低维护成本，提升性能
4. **Phase 4** 扩展生态功能，完善社交登录、身份认证等

整体规划遵循现有代码风格和架构设计，最大化复用现有基础设施（Config 配置表、缓存系统、WebSocket 实时推送、经验值体系等），确保新功能与现有系统无缝集成。
