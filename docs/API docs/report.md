# Report 用户举报接口文档

## 接口概述

`report` 控制器提供**举报**能力：前台用户提交 / 查看 / 撤回自己的举报，后台管理员查看与处理。

| 场景 | 方法 | 权限 |
| :--- | :--- | :--- |
| 前台提交举报 | `POST /api/report/create` | 登录 |
| 前台我的举报 | `GET /api/report/mine` | 登录 |
| 前台撤回举报 | `DELETE /api/report/cancel` | 登录（仅本人的待处理举报） |
| 后台举报列表 | `GET /api/report/all` | 登录 + 权限点（`meta.permit`） |
| 后台处理举报 | `PUT /api/report/handle` | 登录 + 权限点（`meta.permit`） |

### 枚举值

**举报对象类型**（`target_type`，`model.ReportTargets`）：

| 值 | 文案 |
| :--- | :--- |
| `moment` | 动态 |
| `article` | 文章 |
| `comment` | 评论 |
| `user` | 用户 |

**举报原因**（`reason`，`model.ReportReasons`，与前端 `ReportDialog` 选项一一对应）：

| 值 | 文案 |
| :--- | :--- |
| `spam` | 垃圾广告 / 刷屏 |
| `abuse` | 辱骂 / 人身攻击 |
| `porn` | 色情低俗 |
| `illegal` | 违法违规 |
| `politics` | 敏感政治 |
| `infringe` | 侵权 / 抄袭 |
| `harass` | 骚扰 / 恶意私信 |
| `other` | 其他 |

**举报状态**（`status`，`model.Report`）：

| 值 | 文案 | 说明 |
| :--- | :--- | :--- |
| 0 | 待处理 | 新提交的举报 |
| 1 | 已处理 | 管理员判定属实（可同时移除被举报内容） |
| 2 | 已驳回 | 管理员判定不属实 |

---

## 状态码规范

| 状态码 | 说明 | 使用场景 |
| :--- | :--- | :--- |
| **200** | 请求成功 | 正常返回（业务码在 body 的 `code` 字段） |
| **400** | 请求错误 | 参数非法、重复举报、状态不可处理、内容不存在 |
| **401** | 未授权 | 未登录 |
| **403** | 无权限 | 后台接口未授予权限点；撤回他人的举报 |
| **404** | 资源不存在 | 举报记录不存在 |
| **405** | 方法不允许 | method 不存在 |
| **429** | 请求过多 | 当日举报数达到上限（20 条） |

## 接口列表

### 1. POST 请求接口

#### 1.1 提交举报 [业务接口]

- **路径**: `/api/report/create`
- **方法**: `POST`
- **权限**: `type=login`
- **描述**: 提交一条举报。写入时会抓取被举报内容的**快照**（内容后来被删也能追溯），
  并异步给管理员发站内信 / 邮件

**请求参数**:

| 参数名 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| `target_type` | string | **是** | `moment` / `article` / `comment` / `user`（非法值 400） |
| `target_id` | int | **是** | 被举报对象ID；`<=0` 返回 400 |
| `reason` | string | **是** | 举报原因，必须是上表 8 个 key 之一（非法值 400） |
| `detail` | string | 否 | 补充说明，超过 200 字符按字符截断（不报错） |
| `images` | json 数组 或 逗号串 | 否 | 证据图片，最多 3 张；每项必须是 `http://` / `https://` 开头（伪协议会被丢弃），单条 ≤512 字符 |

**成功响应** (200):
```json
{ "code": 200, "msg": "举报已提交，我们会尽快处理！", "data": { "id": 88 } }
```

> 只返回新记录 ID，图片列表要到 `mine` / `all` 里查。

**错误响应**:

| code | msg | 触发条件 |
| :--- | :--- | :--- |
| 401 | `请先登录！` | 未登录 |
| 400 | `举报对象类型不合法！` | `target_type` 不在枚举内 |
| 400 | `target_id 不能为空！` | `target_id <= 0` |
| 400 | `请选择举报原因！` | `reason` 不在枚举内 |
| 400 | `举报的内容不存在或已被删除！` | 目标内容 / 用户查不到 |
| 400 | `不能举报自己！` | 被举报内容属于自己 |
| 400 | `你已经举报过了，我们正在处理中！` | 同一对象已存在**待处理**的举报 |
| 429 | `今天提交的举报太多了，请明天再试！` | 当日举报数 ≥ 20 条 |
| 400 | `提交失败，请稍后再试！` | 写库失败 |

### 2. GET 请求接口

#### 2.1 我的举报 [业务接口]

- **路径**: `/api/report/mine`
- **方法**: `GET`
- **权限**: `type=login`
- **描述**: 分页返回「我提交的举报」

**请求参数**:

| 参数名 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| `page` | int | 否 | 页码，默认 1，上限 100 |
| `limit` | int | 否 | 每页条数，默认 20，上限 50 |

**成功响应** (200):
```json
{
    "code": 200,
    "msg": "查询成功！",
    "data": {
        "data": [
            {
                "id": 88,
                "target_type": "moment",
                "target_id": 12,
                "target_type_text": "动态",
                "target_uid": 3,
                "snapshot": "被举报时的内容快照",
                "images": [],
                "reason": "spam",
                "reason_text": "垃圾广告 / 刷屏",
                "detail": "",
                "status": 0,
                "status_text": "待处理",
                "handle_remark": "",
                "handle_time": 0,
                "remove_content": 0,
                "create_time": 1731000000,
                "reporter": { "id": 7, "nickname": "我" },
                "target_user": { "id": 3, "nickname": "小明" }
            }
        ],
        "count": 3,
        "page": 1
    }
}
```

**响应字段说明**:

| 字段 | 说明 |
| :--- | :--- |
| `images` | 库里存的是逗号串，出网时转成**字符串数组**（无图时为 `[]`） |
| `target_type_text` / `reason_text` / `status_text` | 后端补齐的中文文案 |
| `reporter` / `target_user` | 只含 `id / nickname / avatar / title` 四个公开字段（已做隐私清洗） |
| `handler_uid` | **在 `mine` 中已被移除**（不向举报人暴露处理人），仅 `all` 返回 |
| `page` | 总页数 `ceil(count/limit)` |

**错误响应**: 401 `请先登录！`

#### 2.2 举报列表（后台）[业务接口]

- **路径**: `/api/report/all`
- **方法**: `GET`
- **权限**: 登录 + 权限点（`meta.permit`，未授予返回 403）
- **描述**: 后台举报列表，支持按状态 / 对象类型筛选，并附带待处理总数

**请求参数**:

| 参数名 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| `page` | int | 否 | 页码，默认 1，上限 100 |
| `limit` | int | 否 | 每页条数，默认 20，上限 50 |
| `status` | int / string | 否 | `0` 待处理 / `1` 已处理 / `2` 已驳回；**不传则不过滤** |
| `target_type` | string | 否 | 按对象类型过滤；不传则全部 |

> ⚠️ **筛选 `status=0`（待处理）请传字符串 `"0"`**：后端用 `utils.Is.Empty()` 判空，
> JSON 里的数字 `0` 会被当成「没传」而不过滤。这是项目里多处接口的共有行为
> （例如后台订单列表同样要求 `status: '0'`）。

**成功响应** (200): 结构同 `mine`，差异是**保留 `handler_uid`**，并额外返回 `pending`（待处理总数）：

```json
{
    "code": 200,
    "msg": "查询成功！",
    "data": {
        "data": [
            { "id": 88, "status": 0, "status_text": "待处理", "handler_uid": 0,
              "images": ["https://cdn/a.jpg"], "reporter": { "id": 7 }, "target_user": { "id": 3 } }
        ],
        "count": 120,
        "page": 6,
        "pending": 14
    }
}
```

**错误响应**:

| code | msg | 触发条件 |
| :--- | :--- | :--- |
| 403 | `无权限：当前账号未被授予该权限点！` | 登录了但没有举报管理权限点 |

### 3. PUT 请求接口

#### 3.1 处理举报（后台）[业务接口]

- **路径**: `/api/report/handle`
- **方法**: `PUT`
- **权限**: 登录 + 权限点（`meta.permit`，未授予返回 403）
- **描述**: 处理一条举报（属实 / 驳回），可选同时软删除被举报内容，并异步通知举报人

**请求参数**:

| 参数名 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| `id` | int | **是** | 举报记录ID；`<=0` 返回 400 |
| `status` | int | **是** | **只接受 `1`（已处理）或 `2`（已驳回）**；传 `0` 或其他值返回 400 |
| `remark` | string | 否 | 处理说明，超过 200 字符截断；会随通知发给举报人 |
| `remove_content` | bool / int | 否 | 是否同时移除被举报内容（`1` / `"1"` / `true` 均可）。**仅当 `status=1` 时生效**，且只对 `moment` / `article` / `comment` 生效 —— `user` 类型不会动账号 |

**成功响应** (200):
```json
{ "code": 200, "msg": "已处理！", "data": { "id": 88 } }
```

**错误响应**:

| code | msg | 触发条件 |
| :--- | :--- | :--- |
| 403 | `无权限：当前账号未被授予该权限点！` | 无权限点 |
| 400 | `id 不能为空！` | `id <= 0` |
| 400 | `处理结果只能是「已处理」或「已驳回」！` | `status` 不是 1 / 2 |
| 404 | `举报记录不存在！` | 记录不存在 |
| 400 | `该举报已被处理（已处理），无需重复操作！` | 重复处理（当前状态文案会填进括号） |

### 4. DELETE 请求接口

#### 4.1 撤回举报 [业务接口]

- **路径**: `/api/report/cancel`
- **方法**: `DELETE`
- **权限**: `type=login`（只能撤回**自己**的举报）
- **描述**: 撤回自己「待处理」的举报（**软删除**，进回收站，可由管理员恢复）

**请求参数**:

| 参数名 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| `id` | int | **是** | 举报记录ID；`<=0` 返回 400 |

**成功响应** (200):
```json
{ "code": 200, "msg": "已撤回举报！", "data": { "id": 88 } }
```

**错误响应**:

| code | msg | 触发条件 |
| :--- | :--- | :--- |
| 400 | `id 不能为空！` | `id <= 0` |
| 404 | `举报记录不存在！` | 记录不存在 |
| 403 | `无权操作他人的举报记录！` | 不是本人的举报 |
| 400 | `该举报已被处理，无法撤回！` | 已被处理 / 已驳回 |

## 注意事项

1. **HTTP 状态码恒为 200**，业务码在 body 的 `code`（含 `429` 限流）；
2. **`all` / `handle` 的权限是「登录 + 权限点」双轨**：权限点在控制器里用 `meta.permit` 判定，
   普通用户拿到的是 `403 无权限：当前账号未被授予该权限点！`（与中间件的「无权限！」文案不同）；
3. **同一对象同时只允许一条待处理举报**，重复提交会 400；
4. **防刷上限是每天 20 条**，超出返回 `code:429`（HTTP 仍是 200）；
5. **`images` 是弱校验**：非法项（非 `http(s)`、超长、超过 3 张）会**静默丢弃**，不报错 ——
   前端不要依赖「提交成功 = 图片全部保存」；
6. **`remove_content` 只在 `status=1` 且对象是内容时软删**，`target_type=user` 不会封禁账号
   （封禁是另一套 `user-ban` / 小黑屋流程）；
7. **快照**：`snapshot` 是提交举报时的内容留档，被举报内容后来被编辑或删除都不影响回溯；
8. **撤回是软删除**，而拉黑解除（`user-blocks/unblock`）是物理删除 —— 两者回收站语义不同。
