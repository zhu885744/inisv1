# @提及 接口文档

## 接口概述

`mention` 控制器只对外提供一个接口：**@ 候选用户列表**。

@ 提及本身**没有独立的写入接口** —— 它发生在保存内容的时候：
文章 / 动态 / 独立页 / 评论的控制器在写库前调用 `model.Mention.Parse()`，
把正文里的 `@昵称` 规范化成 `@[昵称](/author/12)`，并给被 @ 的人发站内通知。

> 完整的匹配规则、通知时机、存储格式与前端交互，见功能文档 **`docs/mention.md`**。
> 本文档只描述接口本身。

### 接口类型说明

| 接口类型 | 说明 |
| :--- | :--- |
| **读接口** | `candidates` —— 需登录（`type=login`），只返回「我关注的人」 |
| **写接口** | 无 —— POST / PUT / DELETE 统一返回 405 |

---

## 状态码规范

| 状态码 | 说明 | 使用场景 |
| :--- | :--- | :--- |
| **200** | 请求成功 | 正常返回候选数组 |
| **401** | 未授权 | 未登录 |
| **405** | 方法不允许 | method 不存在，或对写动词调用（`该操作不支持！`） |

---

## 接口列表

### 1. @ 候选用户 [candidates]

- **接口类型**: 业务接口
- **请求方式**: `GET`
- **请求地址**: `/api/mention/candidates`
- **说明**: 返回当前登录用户**已关注的人**作为 @ 候选。未关注的人不会出现在候选里 ——

- **权限**: `type=login`（未登录 401）

  后端保存内容时也只把「已关注的昵称」转成链接，两侧口径一致

**请求参数**:

| 参数名 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| `keyword` | string | 否 | 昵称模糊匹配，默认空（返回全部候选） |
| `limit` | int | 否 | 返回条数，默认 500；`<=0` 或 `>500` 一律按 500 处理（不报错） |

**成功响应** (200):

```json
[
    { "id": 7, "nickname": "Alice", "avatar": "https://..." },
    { "id": 9, "nickname": "Bob", "avatar": "" }
]
```

> ⚠️ 该接口返回**裸数组**（顶层就是 `[...]`），与项目里其它接口的 `{ data, ... }` 风格不同，
> 前端解构时不要套 `res.data.data`（见 `Mellow/src/api/mention.js`）。

**错误响应**:

| code | msg | 触发条件 |
| :--- | :--- | :--- |
| 401 | `请先登录！` | 未登录 |
| 405 | `该操作不支持！` | POST / PUT / DELETE |
| 405 | `方法调用错误：<method> is not in allow` | method 名不存在 |

---

## 特殊说明

1. **候选一次全量取回**（上限 500），前端在本地过滤关键词，避免每敲一个字打一次接口；
2. **昵称为空的用户会被跳过**（无法被 @ 到）；
3. 候选列表与「已关注」强绑定：取关某人后，他既不出现在候选里，正文里的旧 `@昵称` 也不会
   在下次保存时被转成链接（已存在的 `@[昵称](/author/id)` 链接不受影响）；
4. 写入侧没有接口可调：想验证规范化效果，请保存一条含 `@昵称` 的动态，再看落库的 `content`。
