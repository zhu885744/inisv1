## 页面管理 API

### 接口概述

页面管理控制器，提供独立页面的 CRUD 操作及数据统计功能。

### 审核字段说明

| 审核值 | 说明 |
| :--- | :--- |
| **0** | 待审核 - 仅作者与管理员可见 |
| **1** | 已通过 - 访客可见 |
| **2** | 未通过（驳回）- 仅作者与管理员可见，作者在编辑页能看到 `reason` |

`reason`（varchar 512）是**驳回原因**：只有管理员（权限组 `root=1`）能填写，与 `audit` 一起提交；
后端在「审核通过」时会自动清空它，避免作者继续看到已经过期的原因。

### 审核通知说明

页面审核状态变化时会自动发通知 —— **邮件 + 站内信双通道**，只在状态**真正变化**时发送（普通编辑不打扰）：

| 触发时机 | 收件人 | 通知标题 | 邮件场景开关 |
| :--- | :--- | :--- | :--- |
| 进入待审核（audit 变为 0） | 所有超级管理员 | 有新的独立页面待审核 / 有独立页面重新提交待审核 | `page.pending` |
| 审核通过（audit 变为 1） | 页面作者 | 您的独立页面已通过审核 | `page.passed` |
| 审核未通过（audit 变为 2） | 页面作者 | 您的独立页面未通过审核（正文含「驳回原因：xxx」） | `page.rejected` |

- 站内信类型为 `page`，`bind_type=page`、`bind_id=页面 id`；
- 邮件开关在「系统设置 → 邮件通知」（`SYSTEM_MAIL_NOTIFY`），站内信不受开关控制（落库即达）；
- 实现见 `app/api/controller/mail-notify.go` 的 `notifyAuditChange`；后台「页面」列表的驳回弹窗会显示作者与原因输入框。

### 状态码规范

| 状态码 | 含义 | 使用场景 |
| :--- | :--- | :--- |
| 200 | 请求成功 | 成功响应数据 |
| 201 | 创建成功 | 资源创建成功 |
| 202 | 接受请求 | 无实际功能接口 |
| 204 | 无数据 | 查询无结果或无可操作数据 |
| 400 | 请求参数错误 | 参数校验失败、数据操作失败 |
| 401 | 未授权 | 未登录或 token 无效 |
| 405 | 方法不允许 | 调用了不存在的方法 |
| 500 | 服务器错误 | 服务器内部错误 |

### 接口列表

#### 1. 获取指定页面 [one]

**接口类型**: 获取指定

**请求方式**: `GET`

**请求地址**: `/api/pages/one`

**请求参数**:

| 参数名 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| id | int | 否 | 页面ID |
| key | string | 否 | 页面标识 |
| field | string | 否 | 返回字段 |

**响应示例**:

```json
{
  "code": 200,
  "msg": "数据请求成功！",
  "data": {
    "id": 1,
    "key": "about",
    "title": "关于我们",
    "content": "<p>关于我们...</p>",
    "views": 1234,
    "create_time": 1699920000
  }
}
```

### 特殊说明

1. **浏览量统计**: 访问页面时自动更新浏览量，使用 IP+UserAgent 去重，每日同一设备只计数一次
2. **经验值奖励**: 登录用户访问页面可获得经验值奖励
3. **发布时间**: 创建时可指定发布时间，默认为当前时间
4. **审核机制**: 根据系统配置决定是否需要审核
