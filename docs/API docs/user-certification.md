# 用户认证 接口文档

## 接口概述

`user-certification` 控制器提供**用户认证**能力：用户按后台配置的类型提交资料与证明材料，管理员审核通过后，认证标识与认证说明展示在其个人主页。

| 场景 | 方法 | 权限 |
| :--- | :--- | :--- |
| 前台认证摘要（主页展示） | `GET /api/user-certification/one` | 公开 |
| 前台我的认证 | `GET /api/user-certification/mine` | 登录 |
| 前台提交 / 修改申请 | `POST /api/user-certification/apply` | 登录 |
| 后台认证列表 | `GET /api/user-certification/all` | 登录 + 权限点（`meta.permit`） |
| 后台直接授予 | `POST /api/user-certification/grant` | 登录 + 权限点（`meta.permit`） |
| 后台修改资料 | `PUT /api/user-certification/edit` | 登录 + 权限点（`meta.permit`） |
| 后台审核 | `PUT /api/user-certification/handle` | 登录 + 权限点（`meta.permit`） |
| 后台收回 | `DELETE /api/user-certification/revoke` | 登录 + 权限点（`meta.permit`） |

### 字段说明

数据表 `inis_user_certification`（模型 `model.UserCertification`）：

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `id` | int | 主键 |
| `uid` | int | 申请人，**唯一索引**（一人一条） |
| `cert_type` | int | 认证类型，取值见 `cert-type` 控制器 |
| `category` | string | 认证领域，来自类型配置的 `categories` |
| `title` | string | 认证名称，展示在主页昵称旁 |
| `images` | text | 证明材料，逗号分隔的图片 URL |
| `data` | longtext | 自定义字段值（JSON：`{字段key: 值}`） |
| `description` | string | 认证说明，**仅后台填写**（审核通过时写入） |
| `company` / `position` / `contact` | string | 老版本独立列，新提交按同名字段自动回填 |
| `status` | int | `0` 待审核 / `1` 已通过 / `2` 已驳回 |
| `reason` | string | 驳回原因（用户可见，随站内信发出） |
| `handler_uid` / `handle_time` | int | 审核人与审核时间 |
| `expire_time` | int | 有效期，`0` 表示永久 |

### 状态说明

| 值 | 文案 | 可执行操作 |
| :--- | :--- | :--- |
| 0 | 待审核 | 不可重复提交；如需改资料，前端展开表单后再提交 |
| 1 | 已通过 | 主页展示认证标识；可重新提交（回到 0，主页标识暂时下线） |
| 2 | 已驳回 | 按 `reason` 修改后重新提交 |

### 提交流程

1. 前台调用 `GET /api/cert-type/enable` 取启用中的类型与字段定义；
2. 用户选择 `cert_type` 并填写字段，调用 `apply`，字段值放在 `values` 里；
3. 后端先校验该类型的**申请条件**（粉丝数 / 文章数 / 动态数 / 注册天数，见 `cert-type` 的 `conditions`），未达标直接 400；
4. 再按该类型的字段定义校验（必填 / 选项范围 / 数字 / 日期 / 链接协议 / 图片张数与伪协议），
   合法值写入 `data`，其中 `title` / `category` / `images` 额外写回独立列；
5. 管理员调用 `handle` 通过（可同时填写 `description`）或驳回（`reason` 必填）；
6. 审核结果发站内信；通过后 `one` 才开始返回该用户的认证摘要。

运营线下核验过的账号（知名创作者 / 机构）不必走上面的流程：调用 `grant` 直接授予（跳过申请门槛与频率限制，直接落 `status=1`）；已发出的认证需要撤销时调用 `revoke`。

### 权限说明

- `one` 公开：只返回展示型字段，联系方式、证明材料等敏感项不出网；
- `mine` / `apply` 要求登录；
- `all` / `grant` / `edit` / `handle` / `revoke` 在规则里是 `type=login`，再由控制器 `meta.permit` 判定权限点，未授予返回 403。

## 状态码规范

| 状态码 | 说明 | 使用场景 |
| :--- | :--- | :--- |
| 200 | 请求成功 | 查询、提交、审核成功（业务码在 body 的 `code`） |
| 400 | 请求错误 | 字段校验失败、类型不可用、重复提交、提交过于频繁 |
| 401 | 未授权 | 未登录 |
| 403 | 禁止访问 | 已登录但未授予该权限点 |
| 404 | 资源不存在 | 审核的记录不存在 |
| 405 | 方法不允许 | 方法名不存在 |

## 接口列表

### 1. 用户认证摘要 [one]

- **接口类型**: 业务接口
- **请求方式**: `GET`
- **请求地址**: `/api/user-certification/one`
- **权限**: 公开
- **说明**: 主页展示用的认证摘要，只有「已通过且未过期」才返回数据

**请求参数**:

| 参数名 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| `uid` | int | **是** | 用户 ID；`<=0` 返回 400 |

**成功响应** (200):

```json
{
  "code": 200,
  "msg": "查询成功！",
  "data": {
    "id": 8,
    "uid": 7,
    "cert_type": 1,
    "type_text": "职业认证",
    "color": "#e8a020",
    "title": "前端工程师",
    "description": "某某科技前端工程师，专注工程化与性能优化",
    "expire_time": 0,
    "handle_time": 1760000000,
    "fields": [
      {
        "key": "company",
        "label": "公司 / 组织",
        "type": "text",
        "value": "某某科技有限公司",
        "text": "某某科技有限公司"
      }
    ]
  }
}
```

**响应字段说明**:

| 字段 | 说明 |
| :--- | :--- |
| `type_text` | 类型名称，取自 `cert-type` 配置；类型被删时回退内置文案 |
| `color` | 认证标识配色，取 `cert-type` 的 `color`；空串表示由前端按内置兜底色渲染 |
| `title` | 认证名称；记录为空时回退为 `type_text`（保证主页标识不消失） |
| `fields` | 后台标记为「公开展示」且非「仅后台可见」的字段；内置键 `title` / `category` 不重复出现 |

**不返回 `category`（认证领域）**：个人主页的认证区默认只展示认证名称 + 认证说明，领域仅用于申请分类与后台筛选（`mine` / `all` 仍会返回，供表单回填与审核）。

未认证、审核中、已过期、已驳回时 `data` 为 `null`（前端按「无认证」渲染，不是错误）。

**错误响应**: 400 `uid 不能为空！`

### 3. 提交认证申请 [apply]

- **接口类型**: 业务接口
- **请求方式**: `POST`
- **请求地址**: `/api/user-certification/apply`
- **权限**: `type=login`
- **说明**: 首次提交建档，已存在则覆盖更新并回到待审核；类型与字段校验由 `cert-type` 配置决定

**请求参数**:

| 参数名 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| `cert_type` | int | **是** | 类型 ID，必须是启用中的类型 |
| `values` | object | **是** | `{字段key: 值}`，键取该类型配置里的 `fields[].key` |

`values` 传空时会退化为「平铺参数」解析（`title` / `category` / `images` 直接放在顶层），仅为兼容旧前端，新调用方不要依赖。

`description` 不在用户可填范围内：即使传入也会被清空，认证说明只能由后台在审核通过时填写。

**请求示例**:

```json
{
  "cert_type": 1,
  "values": {
    "title": "前端工程师",
    "category": "编程开发",
    "company": "某某科技有限公司",
    "position": "前端工程师",
    "contact": "hi@example.com",
    "images": ["https://cdn/a.jpg"]
  }
}
```

**成功响应** (200):

```json
{
  "code": 200,
  "msg": "已提交，等待管理员审核！",
  "data": {
    "status": 0
  }
}
```

**错误响应**:

| code | msg | 触发条件 |
| :--- | :--- | :--- |
| 401 | `请先登录！` | 未登录 |
| 400 | `请选择认证类型！` | 类型不存在或已停用 |
| 400 | `该认证类型暂未开放申请！` | 类型下没有配置任何字段 |
| 400 | `请填写「认证名称」！` | 必填字段为空（文案随字段 `label` 变化） |
| 400 | `请上传「证明材料」！` | 必填图片字段为空 |
| 400 | `请选择「认证领域」！` | 必填下拉为空 |
| 400 | `「从业年限」需要填写数字！` | 数字字段不是合法数字 |
| 400 | `「作品链接」需要填写 http(s) 链接！` | 链接字段不是 `http(s)` 开头 |
| 400 | `「成立日期」的日期格式应为 YYYY-MM-DD！` | 日期字段格式错误 |
| 400 | `「领域」的取值不在候选范围内！` | 下拉值不在 `options` / `categories` 里 |
| 400 | `申请条件未满足：粉丝数需达到 100（当前 23）；注册天数需达到 30（当前 12）。` | 未达到该类型的 `conditions` 门槛（多项用 `；` 连接） |
| 400 | `申请正在审核中，请耐心等待，无需重复提交！` | 当前记录仍是待审核 |
| 400 | `提交过于频繁，请稍后再试！` | 距上次提交不足 60 秒 |

### 4. 认证列表（后台） [all]

- **接口类型**: 业务接口
- **请求方式**: `GET`
- **请求地址**: `/api/user-certification/all`
- **权限**: 登录 + 权限点（`meta.permit`，未授予返回 403）
- **说明**: 后台认证列表，支持按状态 / 类型 / 用户 / 领域筛选，附带待审核总数与类型筛选项

**请求参数**:

| 参数名 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| `page` | int | 否 | 页码，默认 1，上限 200 |
| `limit` | int | 否 | 每页条数，默认 20，上限 50 |
| `status` | int / string | 否 | `0` 待审核 / `1` 已通过 / `2` 已驳回；空串表示不筛 |
| `cert_type` | int | 否 | 按类型筛选；空串表示不筛 |
| `uid` | int | 否 | 按申请人筛选；空串表示不筛 |
| `category` | string | 否 | 按领域精确筛选 |

筛选统一按「空串 = 不筛」处理，`status=0`（待审核）能被正常筛选，不会被当成「没传」。

**成功响应** (200):

### 5. 审核认证申请 [handle]

- **接口类型**: 业务接口
- **请求方式**: `PUT`
- **请求地址**: `/api/user-certification/handle`
- **权限**: 登录 + 权限点（`meta.permit`，未授予返回 403）
- **说明**: 通过或驳回一条认证申请；通过时可填写认证说明并设置有效期，驳回必须写原因

**请求参数**:

| 参数名 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| `id` | int | **是** | 认证记录 ID；`<=0` 返回 400 |
| `status` | int | **是** | **只接受 `1`（通过）或 `2`（驳回）** |
| `reason` | string | 驳回时必填 | 驳回原因，超过 200 字符截断；随站内信发给用户 |
| `description` | string | 否 | 认证说明，**只有后台能写**；超过 255 字符截断；`status=1` 且传了该键才生效 |
| `expire_days` | int | 否 | 有效期天数，`0` / 不传表示永久 |

**成功响应** (200):

```json
{
  "code": 200,
  "msg": "已处理！",
  "data": {
    "id": 8,
    "status": 1
  }
}
```

**错误响应**:

| code | msg | 触发条件 |
| :--- | :--- | :--- |
| 403 | `无权限：当前账号未被授予该权限点！` | 未授予权限点 |
| 400 | `id 不能为空！` | `id <= 0` |
| 400 | `审核结果只能是「通过」或「驳回」！` | `status` 不是 1 / 2 |
| 400 | `驳回时必须填写原因！` | `status=2` 且 `reason` 为空 |
| 404 | `认证记录不存在！` | 记录不存在或已删除 |

### 6. 修改认证资料（后台） [edit]

- **接口类型**: 业务接口
- **请求方式**: `PUT`
- **请求地址**: `/api/user-certification/edit`
- **权限**: 登录 + 权限点（`meta.permit`，未授予返回 403）
- **说明**: 修改用户提交的字段值 / 证明材料 / 认证说明，**不改变审核状态**（通过、驳回、有效期仍走 `handle`）

**请求参数**:

| 参数名 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| `id` | int | **是** | 认证记录 ID |
| `values` | object | 否 | `{字段key: 值}`；**传了才按该记录类型的配置整体重写，缺失项视为清空**；不传则字段值不变 |
| `description` | string | 否 | 认证说明，超过 255 字符截断；不传保留原值，传空串表示清空 |

与 `apply` 的差异：**必填项不做强制校验**（运营需要能清空某一项，如机构改名后旧字段作废），但格式校验照旧执行——字段类型、下拉选项范围、长度上限、链接 `http(s)` 协议、图片张数与伪协议过滤。

**请求示例**:

```json
{
  "id": 8,
  "values": {
    "title": "资深前端工程师",
    "category": "编程开发",
    "company": "某某科技有限公司",
    "position": "前端负责人",
    "contact": "hi@example.com",
    "images": ["https://cdn/a.jpg"]
  },
  "description": "某某科技前端负责人，专注工程化与性能优化"
}
```

**成功响应** (200):

```json
{
  "code": 200,
  "msg": "已保存！",
  "data": {
    "id": 8
  }
}
```

**错误响应**:

| code | msg | 触发条件 |
| :--- | :--- | :--- |
| 403 | `无权限：当前账号未被授予该权限点！` | 未授予权限点 |
| 400 | `id 不能为空！` | `id <= 0` |
| 404 | `认证记录不存在！` | 记录不存在或已删除 |
| 400 | `该认证类型的配置已删除，无法编辑资料！` | 记录的 `cert_type` 在 `cert-type` 里已不存在 |
| 400 | `该认证类型没有配置任何申请字段！` | 类型字段定义为空 |
| 400 | `「作品链接」需要填写 http(s) 链接！` | 格式类校验失败（文案随字段 `label` 变化） |
| 400 | `没有需要修改的内容！` | 既没传 `values` 也没传 `description` |

`title` 被清空时会回落为类型名称（与 `apply` 一致），保证主页认证标识不消失。

**站内提醒**: 保存成功且**存在实际变化**时，会异步给申请人发一条站内信（`type=system`，`bind_type=user-certification`，`bind_id` 为记录 ID）：

- 标题：`你的认证资料已更新`
- 正文：`你的「前端工程师」认证资料已被管理员更新：认证名称、公司 / 组织。如信息有误，可修改资料后重新提交。`
- 只列**变化的字段名称**，不复述字段值（值里可能含仅后台可见的联系方式）；字段超过 6 项时只报前 6 项并追加「等 N 项」
- 原样保存（无任何字段变化）不会发通知，避免运营点开看一眼就产生噪音
- 通知发送失败不影响保存结果（异步 + recover 兜底）

---

### 7. 直接授予认证（后台） [grant]

- **接口类型**: 业务接口
- **请求方式**: `POST`
- **请求地址**: `/api/user-certification/grant`
- **权限**: 登录 + 权限点（`meta.permit`，未授予返回 403）
- **说明**: 运营线下核验后直接授予认证，不经过用户提交与审核队列，直接落 `status=1`

与 `apply` 的差异：**跳过申请门槛**（粉丝数 / 文章数 / 动态数 / 注册天数）与 **60 秒提交频率限制**——这两项是约束用户自助申请的，运营核实过就不再拦；`handler_uid` / `handle_time` / `expire_time` 随本次授予一并写入。

**请求参数**:

| 参数名 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| `uid` | int | **是** | 被授予的用户 ID；用户不存在返回 404 |
| `cert_type` | int | **是** | 类型 ID，必须是 `cert-type` 中存在的类型（不要求 `enable=1`） |
| `values` | object | 否 | `{字段key: 值}`，键取该类型配置里的 `fields[].key` |
| `description` | string | 否 | 认证说明，超过 255 字符截断 |
| `expire_days` | int | 否 | 有效期天数，`0` / 不传表示永久 |

字段校验与 `apply` 同一套（类型 / 选项范围 / 数字 / 日期 / 链接 `http(s)` / 图片张数与伪协议），但**必填项不强制**：运营手上的资料未必齐全，缺认证名称时回落为类型名称，主页标识不受影响。

`uid` 上有唯一索引，已有记录（待审核 / 已驳回 / 已通过）会被本次内容**整条覆盖**，历史驳回原因一并清空。

**请求示例**:

```json
{
  "uid": 7,
  "cert_type": 1,
  "values": {
    "title": "前端工程师",
    "category": "编程开发",
    "company": "某某科技有限公司"
  },
  "description": "某某科技前端工程师，专注工程化与性能优化",
  "expire_days": 365
}
```

**成功响应** (200):

```json
{
  "code": 200,
  "msg": "已授予认证！",
  "data": {
    "id": 8,
    "uid": 7,
    "status": 1
  }
}
```

**错误响应**:

| code | msg | 触发条件 |
| :--- | :--- | :--- |
| 403 | `无权限：当前账号未被授予该权限点！` | 未授予权限点 |
| 400 | `uid 不能为空！` | `uid <= 0` |
| 404 | `用户不存在！` | `uid` 对应用户不存在或已删除 |
| 400 | `请选择认证类型！` | `cert_type` 不存在 |
| 400 | `「作品链接」需要填写 http(s) 链接！` | 格式类校验失败（文案随字段 `label` 变化） |

**站内提醒**: 授予成功会异步给用户发一条站内信（`type=system`，`bind_type=user-certification`）：

- 标题：`你已获得认证`
- 正文：`管理员已为你的账号授予「前端工程师」认证，现在会展示在你的个人主页。`

与审核通过的通知分开：用户没有提交过申请，文案不写「已通过审核」。

### 8. 收回认证（后台） [revoke]

- **接口类型**: 业务接口
- **请求方式**: `DELETE`
- **请求地址**: `/api/user-certification/revoke`
- **权限**: 登录 + 权限点（`meta.permit`，未授予返回 403）
- **说明**: 收回已发出的认证，记录被删除，主页标识立即消失，用户可重新申请

与 `handle` 驳回的区别：驳回是「这次申请没通过」（用户改资料可重提，`reason` 必填）；收回是「已经发出的认证被撤销」（冒名、资质过期、机构注销等），记录直接删除，用户端看到的就是「未认证」。

**请求参数**:

| 参数名 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| `id` | int | 二选一 | 认证记录 ID，优先使用 |
| `uid` | int | 二选一 | 用户 ID，`id` 为空时按它定位 |
| `reason` | string | 否 | 收回原因，超过 200 字符截断；随站内信发给用户 |

**成功响应** (200):

```json
{
  "code": 200,
  "msg": "已收回认证！",
  "data": {
    "id": 8,
    "uid": 7
  }
}
```

**错误响应**:

| code | msg | 触发条件 |
| :--- | :--- | :--- |
| 403 | `无权限：当前账号未被授予该权限点！` | 未授予权限点 |
| 400 | `id 不能为空！` | `id` 与 `uid` 都未传 |
| 404 | `认证记录不存在！` | 记录不存在或已被收回 |

收回使用**物理删除**：`uid` 上有唯一索引 `uk_cert_uid`，软删除的行仍留在表里，用户重新申请时再插入同一 `uid` 会撞唯一键。需要保留证据时应使用 `edit` 改资料或 `handle` 驳回，而不是 `revoke`。

**站内提醒**: 收回成功会异步给用户发一条站内信：

- 标题：`你的认证已被收回`
- 正文：`「前端工程师」认证已被收回：资质已过期。如资料有变可重新申请。`（未传 `reason` 时省略冒号与原因）

---

## 特殊说明

1. **一人一条**：`uid` 唯一索引，再次提交是覆盖更新，不做多版本堆叠；
2. **重新提交会回到待审核**，并清空上一次的结论（`reason` / `handler_uid` / `handle_time` / `expire_time`）与 `description`，需要管理员重新审核并重新填写认证说明；
3. **待审核期间不能再次提交**（返回 400），两次提交至少间隔 60 秒，用于防止脚本刷审核队列；
4. **认证说明只由后台填写**：用户提交的 `description` 会被忽略并清空，避免主页展示区变成自我宣传位；
5. **老数据兼容**：升级前提交的记录没有 `data`，`fields` 会按同名的独立列（`title` / `category` / `company` / `position` / `contact` / `images`）回落取值；
6. **图片是弱校验**：非 `http(s)`、超长、超过字段 `max_count` 的项会被静默丢弃，不报错，前端不要依赖「提交成功 = 图片全部保存」；
7. **站内信异步发送**：审核结论（含驳回原因）通过站内信通知申请人，发送失败不影响审核结果；
8. **后台可直接修资料**：`edit` 只改字段值与认证说明，不碰 `status` / `handler_uid` / `handle_time` / `expire_time`，修完仍停留在原状态（待审核的仍需审核）；有实际变化时会给用户发站内提醒（见 6. 编辑资料的「站内提醒」）；
9. **主页展示口径**：个人主页的认证区只展示认证名称 + 后台填写的认证说明，**不展示认证领域**；`one` 已不再返回 `category`，`mine` / `all` 仍返回（本人回填 / 后台筛选）；
10. **申请门槛由类型配置决定**：`apply` 先校验 `conditions`（粉丝 / 文章 / 动态 / 注册天数），未达标返回 400；后台 `edit` 不受门槛限制，避免运营改老用户资料时被拦住。条件统计带 3 分钟缓存，关注 / 发布 / 删除 / 审核与类型配置改动会主动失效（见 `cert-type` 的「申请条件说明」）。

11. **直接授予等同一次无条件通过**：`grant` 直接落 `status=1`，不经过 `apply` 的门槛与频率限制；覆盖已有记录时历史驳回原因会被清空；
12. **收回是物理删除**：`revoke` 删除记录（不软删除，原因见 8. 收回认证），收回后 `mine` 返回 `null`，用户可重新申请；
13. **内嵌作者自带认证摘要**：`users/one`、`users/batch` 以及文章 / 评论 / 动态 / 关注列表等接口内嵌的用户对象会带 `cert` 字段（`{uid, cert_type, type_text, color, title}`，无认证时该字段不存在），供头像右下角的认证角标直接渲染；摘要按 `uid` 缓存 60 秒，`apply` / `grant` / `handle` / `edit` / `revoke` 都会主动失效。
