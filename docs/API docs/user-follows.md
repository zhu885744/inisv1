# User Follows 用户关注接口文档

## 接口概述

`user-follows` 控制器用于管理用户关注关系，支持关注、取消关注、获取关注列表和粉丝列表等功能。所有接口均支持缓存优化和权限控制。

### 接口类型说明

| 接口类型 | 说明 |
| :--- | :--- |
| **基础接口** | one、all、rand、count、sum、min、max、column、remove、delete、clear、restore、save、create、update |
| **业务接口** | follow（关注用户）、unfollow（取消关注）、following（获取关注列表）、followers（获取粉丝列表）、is-following（检查是否已关注）、counts（批量查询关注/粉丝数量） |

---

## 状态码规范

| 状态码 | 说明 | 使用场景 |
| :--- | :--- | :--- |
| **200** | 请求成功 | 获取数据成功、操作成功 |
| **202** | 接受请求 | 请求已接受（无实际功能） |
| **204** | 无内容 | 查询无数据、无可操作数据 |
| **400** | 请求错误 | 参数校验失败、操作失败 |
| **401** | 未授权 | 用户未登录 |
| **403** | 无权限 | 无操作权限 |
| **405** | 方法不允许 | 请求方法错误或方法名错误 |
| **500** | 服务器错误 | 系统内部错误 |

## 特殊说明

### 1. 缓存策略
- 所有 GET 查询接口均支持缓存
- POST/PUT/DELETE 数据修改后会自动清除相关缓存

### 2. 权限控制
- 普通用户只能操作自己的关注数据
- 管理员可以操作所有用户的关注数据

### 3. 关注限制
- 用户不能关注自己（会返回 400 错误）

### 4. 状态说明
- `status=1`：已关注
- `status=0`：已取消关注（逻辑取消，非物理删除）

### 5. 关系说明
- **关注列表 (following)**: 当前用户关注了哪些用户
- **粉丝列表 (followers)**: 哪些用户关注了当前用户

### 6. 关注/取消关注特性
- 关注不检查重复，重复关注直接返回成功
- 取消关注不检查是否存在记录，直接更新状态返回成功
- unfollow 同时支持 POST 和 PUT 两种请求方式
