# 内容可见范围 接口文档

## 接口概述

文章、动态、独立页面、评论共用的「可见范围」能力：公开 / 登录可见 / 付费可见（积分兑换）/ 仅作者可见。

> **评论不支持付费可见**：评论只提供「公开 / 登录可见 / 仅作者可见」三档，不参与积分兑换
> （`model.ScopePaySupported("comment") == false`）。历史数据或旧前端传来的 `scope=3`
> 会被统一降级为「登录可见」，兑换接口也会直接拒绝评论。
>
> **仅作者可见只对评论开放**（`model.ScopeAuthorSupported("comment") == true`）：
> 这里的「作者」指**被评论内容（文章 / 动态 / 独立页面）的作者**，评论者本人与管理员同样可看；
> 其他用户只看到「该评论仅作者可见」的占位提示。非评论类型传入 `scope=4` 会按「公开」处理。

实现位置：

- 字段与解锁记录：`app/model/content-unlock.go`
- 接口层判定与脱敏：`app/api/controller/scope.go`
- 兑换接口：`app/api/controller/unlock.go`
- 前端遮罩组件：`Mellow/src/components/ContentLock.vue`

### 字段说明

`article`、`moments`、`pages` 三张表各新增两个字段；`comment` 只有 `scope`（评论不支持付费）：

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `scope` | int | 可见范围：**1 公开**（含访客所有人可见）、**2 登录可见**、**3 付费可见**（仅文章 / 动态 / 独立页面）、**4 仅作者可见**（仅评论）；历史数据 / 0 一律按公开处理 |
| `scope_integral` | int | 付费可见时兑换所需的积分，`scope=3` 时生效（须 > 0）；**评论表没有该字段** |

写入说明：

- `save` / `create` / `update` 支持直接传 `scope`、`scope_integral`（已加入各控制器的 `allowFields`）；
- 不传时数据库默认 `scope=1`、`scope_integral=0`，即公开；
- 作者本人、管理员（含被授予权限点的非 root 分组）不受可见范围限制；
- 文章 / 动态 / 独立页面支持三档，付费可见时兑换积分归作者；
- 评论支持 1 公开 / 2 登录可见 / 4 仅作者可见：创建时 `scope=3` 会被降级为 2，且不接收 `scope_integral`
  （编辑接口不允许改可见范围，保持创建时的设置）；
- 「仅作者可见」的评论不会触发 @ 提及通知，也不会给「被回复的人」发回复通知（避免正文外泄），
  只有内容作者会收到「收到新回复」提示。

### 谁能绕过可见范围

| 身份 | 是否豁免 | 说明 |
| :--- | :--- | :--- |
| 作者本人 | 是 | 始终可查看自己的内容（含付费内容），便于预览与编辑 |
| 管理员 | **仅后台管理界面** | 前端在 `/admin` 路径下自动附加请求头 `X-Requested-With: inis-admin`，后端还需要 `permit` 通过（root 分组或拥有该接口权限点）才豁免 |
| 管理员（前台浏览） | 否 | 前台页面同样会看到「登录后查看 / N 积分兑换」，这样才能验证付费墙是否真的生效 |
| 普通登录用户 | 否 | 登录可见直接可看；付费可见需要兑换 |

> 注意：接口文档里的「管理员」不是指「登录了管理员账号就一定能看全文」——豁免与「是否后台界面」绑定。
> 因此用管理员账号在前台测试付费文章时，看到兑换按钮属于预期；文章作者本人测试则始终直接可见。

### 返回字段

接口在**无权查看**时不会报错，而是：

1. 清空正文字段（文章 / 页面：`content`；动态 / 评论：`content`、`images`）；
2. 在每条数据上追加三个字段：

| 字段 | 说明 |
| :--- | :--- |
| `scope` | 归一化后的可见范围（1 / 2 / 3 / 4；评论不会是 3，非评论不会是 4） |
| `scope_integral` | 兑换所需积分（评论不返回该字段） |
| `scope_state` | **`""` 可查看**、**`login` 需登录**、**`pay` 需积分兑换**、**`author` 仅作者可见**（评论不会出现 `pay`，非评论不会出现 `author`） |

可查看的数据不会新增这三个字段，因此前端用 `scope_state` 是否存在即可判断是否被限制。

> 说明：匿名用户访问付费内容时返回 `scope_state=login`（先登录才能兑换），`scope_integral` 仍会回传，前端可展示「登录后可支付 N 积分查看」。

### 生效的接口

| 控制器 | 已处理接口 |
| :--- | :--- |
| `article` | `one`、`all`、`rand`、`column` |
| `moments` | `one`、`all`、`rand`、`column`、`comment`（动态下的评论） |
| `pages` | `one`、`all`、`rand`、`column` |
| `comment` | `one`、`all`、`rand`、`column`、`flat`（回复树逐层处理；公开 / 登录可见 / 仅作者可见） |
| `topics` | `content`（话题聚合列表） |
| `search` | 非公开内容不返回正文片段 `snippet` |
| `rss` | 非公开文章只输出摘要，不输出全文 |

## 接口列表

### 兑换接口

`GET /api/unlock/check`、`POST /api/unlock/pay`、`GET /api/unlock/list`
（查询可见状态 / 积分兑换 / 我的兑换记录）的详细参数与返回见 [unlock.md](./unlock.md)。

兑换成功后，作者会收到一条站内通知（`type=unlock`，`bind_type/bind_id` 指向被兑换内容）：

> 小朱 兑换了你的文章《标题》内容查看权限
> 对方消耗 10 积分兑换了文章《标题》的查看权限，积分已转入你的账户。

通知只在**真实发生兑换**时发送（重复调用 `pay` 命中幂等分支不会重复通知），
详见 [notification.md](./notification.md) 的「通知触发机制」。

## 特殊说明

### 前端使用约定

1. 详情页（文章 / 独立页面 / 动态卡片 / 评论项）判断 `scope_state === 'login' || 'pay'` 时渲染 `<ContentLock>`；
2. `<ContentLock>` 传参：`state`、`integral`、`bind-type`、`bind-id`；
3. 评论项的 `scope_state === 'author'`（仅作者可见）不走 `<ContentLock>`，改为渲染「该评论仅作者可见」占位，
   并隐藏点赞 / 回复 / 举报入口；
4. 兑换成功后组件 `emit('unlocked')`，父级重新拉取内容即可（此时后端已放行，正文正常返回）；
5. 未登录时组件引导到登录页，登录成功后返回原页面会自动重新请求。
