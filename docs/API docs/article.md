# 文章管理 接口文档

## 接口概述

`article` 控制器用于管理文章内容，支持文章的创建、编辑、查询、删除等操作。包含浏览量统计、经验值奖励机制，支持审核流程、权限控制和**草稿功能**。

> 可见范围（公开 / 登录可见 / 付费可见-积分兑换）见 [content-scope.md](./content-scope.md)：`scope` + `scope_integral` 字段，无权查看时正文会被清空并回传 `scope_state`。

### 接口类型说明

| 接口类型 | 说明 |
| :--- | :--- |
| **基础接口** | 支持15个基础接口：one、all、rand、count、sum、min、max、column、remove、delete、clear、restore、save、create、update |
| **特殊接口** | 浏览量更新、经验值奖励（自动触发） |

### 状态字段说明

| 状态值 | 说明 |
| :--- | :--- |
| **0** | 草稿 - 文章未发布，不对外展示 |
| **1** | 发布 - 文章已发布，可以正常展示 |

### 审核字段说明

| 审核值 | 说明 |
| :--- | :--- |
| **0** | 待审核 - 仅作者与管理员可见 |
| **1** | 已通过 - 访客可见 |
| **2** | 未通过（驳回）- 仅作者与管理员可见，作者会在「我的文章」看到 `reason` |

`reason`（varchar 512）是**驳回原因**：只有管理员（权限组 `root=1`）能填写，与 `audit` 一起提交；
后端在「审核通过」时会自动清空它，避免作者继续看到已经过期的原因。

### 审核通知说明

文章审核状态变化时会自动发通知 —— **邮件 + 站内信双通道**，只在状态**真正变化**时发送（普通编辑保存不打扰任何人）：

| 触发时机 | 收件人 | 通知标题 | 邮件场景开关 |
| :--- | :--- | :--- | :--- |
| 进入待审核（audit 变为 0） | 所有超级管理员 | 有新的文章待审核 / 有文章重新提交待审核 | `article.pending` |
| 审核通过（audit 变为 1） | 文章作者 | 您的文章已通过审核 | `article.passed` |
| 审核未通过（audit 变为 2） | 文章作者 | 您的文章未通过审核（正文含「驳回原因：xxx」） | `article.rejected` |

- 站内信类型为 `article`，`bind_type=article`、`bind_id=文章 id`，消息中心点击可跳到文章详情；
- 邮件开关在「系统设置 → 邮件通知」（`SYSTEM_MAIL_NOTIFY`），站内信不受开关控制（落库即达）；
- 后台「批量审核」在前端是逐条调 `update`，后端按条判定状态，天然不会重复发；
- 实现见 `app/api/controller/mail-notify.go` 的 `notifyAuditChange`。

## 状态码规范

| 状态码 | 说明 | 使用场景 |
| :--- | :--- | :--- |
| **200** | 请求成功 | 获取数据成功、操作成功 |
| **201** | 创建成功 | 新增数据成功 |
| **204** | 无内容 | 查询无数据、无可操作数据 |
| **400** | 请求错误 | 参数校验失败、操作失败 |
| **401** | 未授权 | 用户未登录 |
| **403** | 无权限 | 无操作权限 |
| **405** | 方法不允许 | 请求方法错误或方法名错误 |
| **500** | 服务器错误 | 系统内部错误 |

## 接口列表

### 1. 获取单个文章 [one]

- **接口类型**: 基础接口 / 获取指定
- **请求方式**: `GET`
- **请求地址**: `/api/article/one`
- **说明**: 根据条件获取单篇文章

**请求参数**:

| 参数名 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| `id` | int | 否 | 文章ID |
| `field` | string | 否 | 返回字段，逗号分隔 |
| `where` | json | 否 | 条件查询 |
| `like` | json | 否 | 模糊查询 |
| `withTrashed` | bool | 否 | 是否包含已删除数据 |
| `onlyTrashed` | bool | 否 | 是否只查询已删除数据 |

**成功响应** (200):

```json
{
    "code": 200,
    "msg": "数据请求成功！",
    "data": {
        "id": 1,
        "title": "文章标题",
        "abstract": "文章摘要",
        "content": "文章内容",
        "views": 100,
        "create_time": 1699900000
    }
}
```

**特殊说明**: 获取文章时会自动更新浏览量和用户经验值

## 特殊说明

### 1. 浏览量统计
- 浏览量采用 IP+User-Agent 去重机制
- 同一设备一天内访问同一篇文章只计一次浏览

### 2. 经验值奖励
- 用户查看文章时会自动获得经验值
- 经验值记录类型为 `visit`，绑定类型为 `article`

### 3. 审核流程
（统一口径见 `app/api/controller/audit.go`，文章 / 动态 / 独立页面一致）

| 操作 | ARTICLE.audit=1（开启审核） | ARTICLE.audit=0（关闭审核） |
| :--- | :--- | :--- |
| 新建-存草稿 | audit=1, status=0 | audit=1, status=0 |
| 新建-发布 | audit=0, status=1（待审核） | audit=1, status=1（直接通过） |
| 编辑-存草稿 | audit=1, status=0 | audit=1, status=0 |
| 编辑-发布 | 原为草稿 → audit=0（首次发布进入待审核）；已有文章保持原审核状态，二次编辑保存不会被打回待审核 | audit=1, status=1（直接通过） |

- 编辑时未传 `status` 则沿用原文状态，避免把已发布的文章降级成草稿；
- 管理员可以设置 `top` 和 `audit` 字段（提交的 `audit` 优先级最高，会覆盖上面的判定）。

### 4. 缓存策略
- 所有查询接口均支持缓存
- 数据修改后会自动清除相关缓存

### 5. 字段处理
- `covers` 和 `tags` 支持数组格式，会自动序列化
- `json` 类型字段会自动序列化
