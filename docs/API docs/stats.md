## 数据统计（stats）

后台「数据统计」页（`/admin/stats`）的资源告警阈值接口。

> 页面上的实时数据（秒级资源曲线、数据库与缓存状态、在线人数）**走 WebSocket 推送**，见 `docs/socket.md`；
> 这里只有阈值读写。历史趋势（跨天 / 跨小时）功能已移除，采样结果不落库。

| 项 | 说明 |
| :--- | :--- |
| 控制器 | `app/api/controller/stats.go` |
| 采样与判定 | `app/model/stats.go` + `app/timer/stats.go`（按 `stats.sample_interval` 采样，**默认 60 秒**） |
| 权限 | 读写均为 `type=default`（需要权限点，超管默认拥有）；保存阈值额外要求超管（非 root 返回 403） |

---

### GET /api/stats/alert

读取告警阈值。

```json
{
  "code": 200,
  "msg": "查询成功！",
  "data": { "enabled": 0, "cpu": 90, "mem": 90, "disk": 90, "cooldown": 1800 }
}
```

### POST /api/stats/alert

保存告警阈值，**仅超级管理员**。

| 参数 | 类型 | 说明 |
| :--- | :--- | :--- |
| `enabled` | int | `0` 关闭（默认）/ `1` 开启 |
| `cpu` / `mem` / `disk` | int | 使用率阈值（%），收敛到 1~100 |
| `cooldown` | int | 同类告警的最小通知间隔（秒），收敛到 60~86400 |

返回实际落库的配置（越界值已被收敛，前端可直接用它回填表单）。

**存储**：`config` 表的 `SYSTEM_ALERT_THRESHOLD` 记录（值在 `json` 字段），
写入后会清理 `config[SYSTEM_ALERT_THRESHOLD]` 缓存，立即生效。

---

### 采样与告警行为

采样由 `app/timer/stats.go` 按 `config/app.toml` 的 `stats.sample_interval`（默认 60 秒）执行，
**不判断有没有管理员在线** —— 阈值判定必须 24 小时持续，否则就成了「没打开后台就收不到告警」。

单次采样只做 3 个 syscall（CPU / 内存 / 磁盘）+ 一次配置读取，**不写库、不查各表 COUNT**。

命中阈值时：

1. 给所有超级管理员发**站内信**（无开关，落库即投递，保证不漏看）；
2. 同时给管理员发**邮件**，受「系统设置 → 邮件通知 → 系统监控 / 资源告警」场景开关控制；
3. 同类告警在 `cooldown` 内不重复通知（冷却记录在服务端进程内存里，缓存没开也生效）。

邮件正文包含告警项、当前值 / 阈值与采样时间，最后一行是站点地址。站点地址的取值顺序
（见 `MailNotifySiteURL`）：

1. `config/app.toml` 的 `app.domain`（显式配置，最准）；
2. 最近一次请求推导出的站点地址 —— 后台任务没有请求上下文，只能取这个
   （中间件 `app/middleware/params.go` 的 `domain()` 会把它写进缓存与进程内存）；
3. 都取不到时**整行省略**，不会出现「站点：」这样只有标签的悬空行。

前端「数据统计」页会在阈值命中时把对应资源卡片描红并挂「超阈值」角标。

> 关于「会不会把数据库撑爆」：本功能**不落库**，没有任何统计表，所以不存在这个问题。
