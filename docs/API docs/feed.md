# Feed 聚合流接口文档

## 接口概述

`feed` 控制器提供**聚合流**（关注 / 推荐 / 热门）读取能力，是 `/feed` 页面的数据来源。
控制器只有一个对外方法，且**全局只读**：POST / PUT / DELETE 一律拒绝。

三条流的口径（`app/api/controller/feed.go`）：

| 流 | `type` | 口径 |
| :--- | :--- | :--- |
| 关注 | `follow` | 我关注的人发布的动态，按发布时间倒序（DB 分页） |
| 推荐 | `recommend` | 近 30 天、**我没关注过**的公开动态，按热度排序 |
| 热门 | `hot` | 近 30 天全站公开动态，按热度排序 |

- 三者都只包含**已发布且审核通过**的动态（`audit=1`、`status=1`），草稿 / 待审核不会出现；
- 热度权重：点赞 ×1 + 评论 ×2 + 收藏 ×3；
- 推荐 / 热门**只统计近 30 天**（`feedHotDays`），且候选池只取最近 300 条（`feedMaxWindow`）——
  很久以前的高分内容不会再出现；
- 热门流结果缓存 60 秒。

### 接口类型说明

| 接口类型 | 说明 |
| :--- | :--- |
| **读接口** | `all` —— 需登录（`type=login`），未登录 401 |
| **写接口** | 无 —— POST / PUT / DELETE 统一返回 405 |

---

## 状态码规范

| 状态码 | 说明 | 使用场景 |
| :--- | :--- | :--- |
| **200** | 请求成功 | 正常返回（业务码在 body 的 `code` 字段） |
| **400** | 请求错误 | `type` 不在白名单 |
| **401** | 未授权 | 未登录（body 带 `"auth":"guest"`） |
| **405** | 方法不允许 | method 不在 allow；或对只读接口发起了 POST / PUT / DELETE |

---

## 接口列表

### 1. GET 请求接口

#### 1.1 获取聚合流 [业务接口]

- **路径**: `/api/feed/all`
- **方法**: `GET`
- **权限**: `type=login`（必须登录，未登录 401）
- **描述**: 按 `type` 返回关注流 / 推荐流 / 热门流中的一种

**请求参数**:

| 参数名 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| `type` | string | 否 | 流类型：`follow`（默认）/ `recommend` / `hot`；其他值返回 400 |
| `page` | int | 否 | 页码，默认 1；`<=0` 归 1，**`>30` 静默钳到 30**（不报错） |
| `limit` | int | 否 | 每页条数，默认 10；`<=0` 归 10，**`>20` 静默钳到 20**（不报错） |

**成功响应** (200):
```json
{
    "code": 200,
    "msg": "数据请求成功！",
    "data": {
        "data": [
            {
                "id": 12,
                "uid": 3,
                "content": "今天去了 #[旅行](/topic/12) 的路线",
                "images": "",
                "location": "",
                "top": 0,
                "views": 8,
                "audit": 1,
                "status": 1,
                "tags": "|12|",
                "create_time": 1731000000,
                "publish_time": 1731000000,
                "result": {
                    "author": { "id": 3, "nickname": "小明", "avatar": "https://...", "title": null },
                    "comment": { "allow": 1, "show": 1, "count": 2 }
                }
            }
        ],
        "count": 57,
        "page": 6,
        "type": "follow"
    }
}
```

**响应字段说明**:

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `data` | array | 动态列表，字段同 `moments` 表 + `result.author` / `result.comment` |
| `count` | int | `follow`：命中总条数；`hot` / `recommend`：**候选池总数（≤ 300）** |
| `page` | number | **总页数** `ceil(count/limit)`，不是当前页码 |
| `type` | string | 回显实际生效的流类型 |

**错误响应**:

| code | msg | 触发条件 |
| :--- | :--- | :--- |
| 401 | `请先登录！` | 未登录（body 带 `"auth":"guest"`） |
| 400 | `type 只支持 follow / recommend / hot！` | `type` 非法 |
| 405 | `方法调用错误：<method> is not in allow` | method 名不存在 |

---

### 2. POST / PUT / DELETE 请求接口

聚合流是只读接口，任意 method 都返回：

```json
{ "code": 405, "msg": "聚合流为只读接口，不支持该操作！", "data": null }
```

> ⚠️ **未登记权限规则的方法会先被中间件拦成 401**：匿名调用 `POST /api/feed/xxx`
> 得到的是 401（不是控制器的 405），只有携带有效 token 才会看到上面这条只读提示。

---

## 注意事项

1. **HTTP 状态码恒为 200**，业务码在 body 的 `code` —— 按 HTTP 状态做错误处理会失效；
2. **`page` / `limit` 是静默钳制**：传 `limit=100` 只会返回 20 条，且响应**不回显生效值**，
   前端若按自己传的值算分页会错位；
3. **`count` 语义分两种**（提到过，这里强调）：推荐 / 热门最多 300，不是全站总数；
4. **只统计近 30 天**：推荐 / 热门看不到更早的高分内容，前端空态文案不要写「全站热门」；
5. **拉黑与缓存**：热门流的缓存 key 里带「**拉黑集合指纹**」，所以拉黑 / 解除拉黑后立即生效；
   没有拉黑任何人的用户（绝大多数）共享同一份缓存，命中率不受影响。
   关注流 / 推荐流的 key 本来就走 uid，拉黑同样立即生效；
6. 本接口**只返回公开动态**，不提供查看草稿 / 待审核的入口（那是「创作中心 → 我的动态」的职责）。
