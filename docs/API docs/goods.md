# Goods API 文档

## 接口概述

Goods 控制器负责积分商城功能，包含商品管理、订单管理、商品兑换购买、订单取消退款与确认收货。用户通过任务赚取积分（见 [Integral API 文档](integral.md)），再用积分兑换商品。

**接口类型**：业务接口 + 通用 CRUD（商品管理）

### 商品类型

| 类型值 | 名称 | 说明 |
| :--- | :--- | :--- |
| `virtual` | 虚拟商品 | 购买后立即自动发货 |
| `physical` | 实物商品 | 购买前需填写收货地址，管理员发货 |

### 虚拟商品发货方式

| 发货方式 | 名称 | 说明 |
| :--- | :--- | :--- |
| `text` | 文本内容 | 购买后直接展示预设的文本内容 |
| `card` | 卡密 | 购买后从卡密池随机发放一个卡密（抽取后自动移除） |

### 订单状态

| 状态值 | 名称 | 说明 |
| :--- | :--- | :--- |
| 0 | 待发货 | 实物商品等待管理员发货 |
| 1 | 已发货 | 管理员已发货（可附物流信息） |
| 2 | 已完成 | 订单完成（虚拟商品自动完成） |
| 3 | 已取消 | 用户/管理员取消，**积分已退还、库存与销量已回滚** |

### 兑换限制（商品维度）

| 字段 | 说明 |
| :--- | :--- |
| `limit_per_user` | 每人限购数量（0 = 不限购），按有效订单数统计（已取消订单不计入） |
| `min_exp` | 兑换所需最低经验值（0 = 不限），用于等级门槛 |
| `start_time` / `end_time` | 兑换时间窗口（0 = 不限），过期后不可兑换 |
| `sort` | 排序权重（越大越靠前，列表默认 `sort desc, id desc`） |

---

## 状态码规范

| 状态码 | 使用场景 |
|--------|----------|
| 200 | 接口调用成功且数据返回正常 |
| 202 | 业务处理失败但有特定原因（如积分不足、库存不足、卡密不足、已达限购） |
| 204 | 无数据 |
| 400 | 请求参数错误 |
| 401 | 未登录 |
| 403 | 无权限（非管理员） |

#### 1. 商品列表 [业务接口]

**请求方式**：GET
**请求路径**：`/api/goods/all`

**说明**：获取商品列表（公开接口，无需登录）。普通用户仅返回上架商品；管理员默认返回全部，可传 `status` 参数过滤。

**请求参数**：

| 参数名 | 类型 | 必填 | 默认值 | 说明 |
|--------|------|------|--------|------|
| page | int | 否 | 1 | 页码 |
| limit | int | 否 | 系统配置 | 每页数量 |
| order | string | 否 | sort desc, id desc | 排序（白名单：sort/price/stock/sold/create_time/id 的 desc/asc） |
| status | int | 否 | - | 商品状态过滤（仅管理员有效） |
| category | string | 否 | - | 分类筛选 |
| keyword | string | 否 | - | 商品名称关键词搜索 |

**响应字段**（数组项）：

| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | int | 商品 ID |
| title | string | 商品名称 |
| description | string | 商品描述 |
| cover | string | 商品封面 |
| price | int | 积分价格 |
| stock | int | 库存 |
| sold | int | 已兑换数量 |
| status | int | 状态（0下架 1上架） |
| type | string | 商品类型（virtual/physical） |
| category | string | 商品分类 |
| limit_per_user | int | 每人限购（0 = 不限） |
| min_exp | int | 兑换所需最低经验值（0 = 不限） |
| start_time / end_time | int64 | 兑换时间窗口（0 = 不限） |
| sort | int | 排序权重 |
| **can_buy** | bool | 当前登录用户是否可兑换（未登录时仅按商品维度判断） |
| **buy_reason** | string | 不可兑换原因（已售罄 / 未开始 / 已结束 / 需经验 N / 已达限购 / 积分不足） |
| **limit_remain** | int | 限购剩余数量（-1 = 不限购，0 = 已用完） |
| **my_bought** | int | 我已兑换数量（未登录恒为 0） |

> 注：`deliver_content`（文本发货内容）和 `cards`（卡密池）为敏感字段，仅管理员可见，普通用户查询不返回。

#### 4. 购买商品 [业务接口]

**请求方式**：POST
**请求路径**：`/api/goods/buy`

**说明**：使用积分兑换商品（需登录）。虚拟商品购买后立即发货；实物商品需先填写收货地址，购买后生成待发货订单。

**请求参数**：

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| goods_id | int | 是 | 商品 ID |
| address | string | 否 | 收货地址 JSON 字符串（实物商品必填） |

**address 参数结构**（JSON 字符串）：

```json
{
  "name": "张三",
  "phone": "13800138000",
  "address": "广东省深圳市..."
}
```

**兑换前置校验**（在事务内依次执行，任一失败即回滚）：

1. 商品存在且为上架状态
2. 兑换时间窗口（`start_time` / `end_time`）
3. 实物商品必须有收货地址
4. 卡密商品卡密池非空
5. 经验门槛（`min_exp`）
6. 每人限购（`limit_per_user`，不含已取消订单）
7. 库存原子扣减（`stock > 0` 条件更新，防超卖）
8. 积分余额充足

**成功响应**：

```json
{
  "code": 200,
  "msg": "购买成功！",
  "data": {
    "order_id": 10,
    "order_no": "G2026091915302212345678",
    "price": 100,
    "integral": 25,
    "status": 2,
    "deliver_content": "这是一个卡密：ABCD-EFGH",
    "limit_remain": 1
  }
}
```

| 字段 | 说明 |
|------|------|
| order_id | 订单 ID |
| order_no | 订单号（唯一） |
| price | 消耗积分 |
| integral | 购买后剩余积分余额 |
| status | 订单状态（虚拟商品为 2 已完成，实物为 0 待发货） |
| deliver_content | 发货内容（虚拟商品：文本/卡密；实物商品为空） |
| limit_remain | 该商品限购剩余数量（-1 = 不限购） |

**失败响应**（202）：

| 状态码 | msg | 说明 |
|--------|-----|------|
| 202 | 商品不存在！ | 商品 ID 无效 |
| 202 | 商品已下架！ | 商品已下架 |
| 202 | 兑换尚未开始！ / 兑换活动已结束！ | 不在兑换时间窗口内 |
| 202 | 商品库存不足！ | 库存为 0 |
| 202 | 卡密库存不足！ | 卡密池为空 |
| 202 | 经验值达到 N 才可兑换！ | 未达经验门槛 |
| 202 | 已达每人限购上限！ | 超过限购数量 |
| 202 | 积分不足！ | 积分余额不够 |
| 202 | 请填写收货地址！ | 实物商品未填地址 |

#### 7. 取消订单 [业务接口]

**请求方式**：PUT
**请求路径**：`/api/goods/cancel-order`

**说明**：取消订单并**原路退还积分**（需登录）。仅「待发货」（status = 0）订单可取消；虚拟商品下单即完成，不涉及取消。管理员可通过 `order-status` 取消任意订单。

**请求参数**：

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| id | int | 是 | 订单 ID |

**事务内处理**：

1. 校验订单归属与状态（仅 status = 0）
2. 回滚库存 `stock + 1`
3. 回滚销量 `sold - 1`（不小于 0）
4. 退还积分 `integral + price`，写入 `refund` 类型积分流水（含 `balance_after` 快照）
5. 订单状态置为 3，记录 `refund` 与 `cancel_time`

**成功响应**：

```json
{
  "code": 200,
  "msg": "订单已取消，积分已退还！",
  "data": {
    "id": 10,
    "status": 3,
    "refund": 100,
    "integral": 125
  }
}
```

**失败响应**（202）：无权操作该订单！ / 订单已取消！ / 当前订单状态不可取消！

## 特殊说明

### 购买流程

1. **虚拟商品**（text/card）：用户点击兑换 → 确认 → 立即发货 → 订单状态为「已完成」，发货内容展示在订单中。
2. **实物商品**：用户点击兑换 → 填写收货地址 → 生成「待发货」订单 → 管理员后台发货（可填物流）→「已发货」→ 用户确认收货 / 管理员置为「已完成」。

### 取消与退款流程

```
待发货(0) --用户取消/管理员取消--> 已取消(3)
              ├─ 库存 +1、销量 -1
              ├─ 积分原路退还（写 refund 流水）
              └─ 记录 refund / cancel_time
```

- 仅「待发货」订单可取消，避免虚拟商品已发货后被取消
- 取消操作全程在数据库事务中执行，避免出现「退了积分没回滚库存」的不一致

### 卡密发放机制

卡密商品购买时，从卡密池随机抽取一个卡密写入订单的 `deliver_content`，并将该卡密从池中移除（事务保证原子性），防止重复发放。卡密池为空时购买失败并回滚。

### 限购与门槛

- 限购统计口径：该用户对该商品的**未取消订单数**（`status != 3`）
- 经验门槛基于用户 `exp` 字段，与等级体系（`/api/level`）天然对应
- 列表接口已返回 `can_buy` / `buy_reason` / `limit_remain`，前端无需重复计算

### 权限规则（auth-rules）

`goods` 控制器各接口在 `app/model/auth-rules.go` 中登记，规则类型（type）说明：

| type | 含义 | 接口 |
| :--- | :--- | :--- |
| `common` | 公开接口，无需登录 | `all`、`one`、`categories`、`count` |
| `login` | 需登录 | `orders`、`order-one`、`my-stats`、`buy`、`cancel-order`、`receive` |
| `root` | 需管理员权限点 | `orders-all`、`stats`、`save`/`create`、`update`/`restore`、`order-status`、`remove`/`delete`/`clear` |

> 新增接口必须在 `createAuthRules()` 的 `goods` 分组中登记，否则中间件会走「默认」分支要求权限点，普通用户将直接收到 403。

### 安全机制

- `cards`（卡密池）和 `deliver_content`（文本发货内容）为敏感字段，仅管理员可见，普通用户查询商品时不返回，防止白嫖
- 购买走数据库事务，扣库存用原子条件更新（防超卖），扣积分校验余额
- 列表排序与积分明细排序均使用**白名单**校验，防止 SQL 注入
- 订单号由「时间 + 用户 + 随机数」生成并建立唯一索引，防止重复订单
