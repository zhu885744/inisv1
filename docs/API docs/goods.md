# Goods API 文档

## 接口概述

Goods 控制器负责积分商城功能，包含商品管理、订单管理、商品兑换购买。用户通过任务赚取积分（见 [Integral API 文档](integral.md)），再用积分兑换商品。

**接口类型**：业务接口 + 通用 CRUD（商品管理）

### 商品类型

| 类型值 | 名称 | 说明 |
| :--- | :--- | :--- |
| `virtual` | 虚拟商品 | 购买后立即自动发货 |
| `physical` | 实物商品 | 购买前需填写收货地址，管理员发货 |

### 虚拟商品发货方式

| 发货方式 | 名称 | 说明 |
| :--- | :--- | :--- |
| `text` | 文本内容 | 购买后直接展示预设的文本内容 |
| `card` | 卡密 | 购买后从卡密池随机发放一个卡密（抽取后自动移除） |

### 订单状态

| 状态值 | 名称 | 说明 |
| :--- | :--- | :--- |
| 0 | 待发货 | 实物商品等待管理员发货 |
| 1 | 已发货 | 管理员已发货（可附物流信息） |
| 2 | 已完成 | 订单完成（虚拟商品自动完成） |

---

## 状态码规范

| 状态码 | 使用场景 |
|--------|----------|
| 200 | 接口调用成功且数据返回正常 |
| 202 | 业务处理失败但有特定原因（如积分不足、库存不足、卡密不足） |
| 400 | 请求参数错误 |
| 401 | 未登录 |
| 403 | 无权限（非管理员） |

## 接口列表

### 业务接口

#### 1. 商品列表 [业务接口]

**请求方式**：GET  
**请求路径**：`/api/goods/all`

**说明**：获取商品列表（公开接口，无需登录）。普通用户仅返回上架商品；管理员默认返回全部，可传 `status` 参数过滤。

**请求参数**：

| 参数名 | 类型 | 必填 | 默认值 | 说明 |
|--------|------|------|--------|------|
| page | int | 否 | 1 | 页码 |
| limit | int | 否 | 系统配置 | 每页数量 |
| order | string | 否 | create_time desc | 排序 |
| status | int | 否 | - | 商品状态过滤（仅管理员有效） |

**响应字段**（数组项）：

| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | int | 商品 ID |
| title | string | 商品名称 |
| description | string | 商品描述 |
| cover | string | 商品封面 |
| price | int | 积分价格 |
| stock | int | 库存 |
| status | int | 状态（0下架 1上架） |
| type | string | 商品类型（virtual/physical） |
| deliver_type | string | 发货方式（text/card，仅虚拟商品） |

> 注：`deliver_content`（文本发货内容）和 `cards`（卡密池）为敏感字段，仅管理员可见，普通用户查询不返回。

#### 2. 商品详情 [业务接口]

**请求方式**：GET  
**请求路径**：`/api/goods/one`

**说明**：获取单个商品详情（公开接口）

**请求参数**：

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| id | int | 是 | 商品 ID |

#### 3. 购买商品 [业务接口]

**请求方式**：POST  
**请求路径**：`/api/goods/buy`

**说明**：使用积分兑换商品（需登录）。虚拟商品购买后立即发货；实物商品需先填写收货地址，购买后生成待发货订单。

**请求参数**：

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| goods_id | int | 是 | 商品 ID |
| address | string | 否 | 收货地址 JSON 字符串（实物商品必填） |

**address 参数结构**（JSON 字符串）：

```json
{
  "name": "张三",
  "phone": "13800138000",
  "address": "广东省深圳市..."
}
```

**成功响应**：

```json
{
  "code": 200,
  "msg": "购买成功！",
  "data": {
    "order_id": 10,
    "price": 100,
    "integral": 25,
    "status": 2,
    "deliver_content": "这是一个卡密：ABCD-EFGH"
  }
}
```

| 字段 | 说明 |
|------|------|
| order_id | 订单 ID |
| price | 消耗积分 |
| integral | 购买后剩余积分余额 |
| status | 订单状态（虚拟商品为 2 已完成） |
| deliver_content | 发货内容（虚拟商品：文本/卡密；实物商品为空） |

**失败响应**（202）：

| 状态码 | msg | 说明 |
|--------|-----|------|
| 202 | 商品不存在！ | 商品 ID 无效 |
| 202 | 商品已下架！ | 商品已下架 |
| 202 | 商品库存不足！ | 库存为 0 |
| 202 | 卡密库存不足！ | 卡密池为空 |
| 202 | 积分不足！ | 积分余额不够 |
| 202 | 请填写收货地址！ | 实物商品未填地址 |

#### 4. 我的订单 [业务接口]

**请求方式**：GET  
**请求路径**：`/api/goods/orders`

**说明**：查询当前登录用户的订单列表（需登录，仅返回自己的订单）

**请求参数**：

| 参数名 | 类型 | 必填 | 默认值 | 说明 |
|--------|------|------|--------|------|
| page | int | 否 | 1 | 页码 |
| limit | int | 否 | 系统配置 | 每页数量 |

**响应字段**（数组项）：

| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | int | 订单 ID |
| uid | int | 用户 ID |
| goods_id | int | 商品 ID |
| price | int | 成交积分价格 |
| status | int | 订单状态（0待发货 1已发货 2已完成） |
| deliver_content | string | 发货内容（虚拟商品：文本/卡密） |
| logistics | string | 物流信息（实物商品发货后） |
| result.goods | object | 商品信息（id/title/cover/price/type） |
| result.address | object | 收货地址（实物商品，含 name/phone/address） |
| create_time | int64 | 下单时间戳 |

#### 5. 全部订单 [业务接口-管理员专用]

**请求方式**：GET  
**请求路径**：`/api/goods/orders-all`

**说明**：查询全部订单（仅管理员），支持按用户、状态过滤

**权限要求**：仅 root 用户（管理员）可调用

**请求参数**：

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| uid | int | 否 | 按用户 ID 过滤 |
| status | int | 否 | 按订单状态过滤 |
| page | int | 否 | 页码 |
| limit | int | 否 | 每页数量 |

#### 6. 更新订单状态 [业务接口-管理员专用]

**请求方式**：PUT  
**请求路径**：`/api/goods/order-status`

**说明**：更新订单状态（仅管理员），实物商品发货时可附带物流信息

**权限要求**：仅 root 用户（管理员）可调用

**请求参数**：

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| id | int | 是 | 订单 ID |
| status | int | 是 | 订单状态（0/1/2） |
| logistics | string | 否 | 物流信息（发货时填写） |

**成功响应**：

```json
{
  "code": 200,
  "msg": "更新成功！",
  "data": {
    "id": 10,
    "status": 1
  }
}
```

### 商品管理接口（管理员专用）

以下接口均需 root 权限，用于商品增删改：

| HTTP | method | 路径 | 说明 |
| :--- | :--- | :--- | :--- |
| POST | `save` | `/api/goods/save` | 保存商品（有 `id` 更新，无则创建） |
| POST | `create` | `/api/goods/create` | 创建商品 |
| PUT | `update` | `/api/goods/update` | 更新商品 |
| PUT | `restore` | `/api/goods/restore` | 恢复软删除商品 |
| DELETE | `remove` | `/api/goods/remove` | 软删除商品 |
| DELETE | `delete` | `/api/goods/delete` | 彻底删除商品 |
| DELETE | `clear` | `/api/goods/clear` | 清空回收站 |

**商品字段**：

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| title | string | 是 | 商品名称 |
| description | string | 否 | 商品描述 |
| cover | string | 否 | 封面图片 URL |
| price | int | 是 | 积分价格 |
| stock | int | 是 | 库存 |
| status | int | 否 | 状态（0下架 1上架，默认 1） |
| type | string | 否 | 商品类型（virtual/physical，默认 virtual） |
| deliver_type | string | 否 | 发货方式（text/card，仅虚拟商品） |
| deliver_content | string | 否 | 文本发货内容（text 类型） |
| cards | string | 否 | 卡密池 JSON 数组（card 类型） |

**cards 字段示例**：

```json
["卡密1-ABC", "卡密2-DEF", "卡密3-GHI"]
```

## 特殊说明

### 购买流程

1. **虚拟商品**（text/card）：用户点击兑换 → 确认 → 立即发货 → 订单状态为「已完成」，发货内容展示在订单中。
2. **实物商品**：用户点击兑换 → 填写收货地址 → 生成「待发货」订单 → 管理员后台发货（可填物流）→「已发货」→「已完成」。

### 卡密发放机制

卡密商品购买时，从卡密池随机抽取一个卡密写入订单的 `deliver_content`，并将该卡密从池中移除（事务保证原子性），防止重复发放。卡密池为空时购买失败并回滚。

### 安全机制

- `cards`（卡密池）和 `deliver_content`（文本发货内容）为敏感字段，仅管理员可见，普通用户查询商品时不返回，防止白嫖。
- 购买走数据库事务，扣库存用原子条件更新（防超卖），扣积分校验余额。
