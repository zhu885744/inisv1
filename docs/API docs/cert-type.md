# 认证类型配置 接口文档

## 接口概述

`cert-type` 控制器提供**认证类型配置**能力：一个类型即一套认证表单（类型名称 / 认证说明 / 认证领域 / 申请字段），全部由后台维护，前台按配置动态渲染申请页。

| 场景 | 方法 | 权限 |
| :--- | :--- | :--- |
| 前台申请页读取类型 | `GET /api/cert-type/enable` | 公开 |
| 后台类型列表 | `GET /api/cert-type/all` | 登录 + 权限点（`meta.permit`） |
| 后台新建类型 | `POST /api/cert-type/create` | 登录 + 权限点（`meta.permit`） |
| 后台修改类型 | `PUT /api/cert-type/update` | 登录 + 权限点（`meta.permit`） |
| 后台删除类型 | `DELETE /api/cert-type/remove` | 登录 + 权限点（`meta.permit`） |

### 字段说明

数据表 `inis_cert_type`（模型 `model.CertType`）：

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `id` | int | 主键，同时是认证记录的 `cert_type` 取值 |
| `name` | string | 类型名称，展示在前台下拉与主页认证标识旁 |
| `icon` | string | Bootstrap Icons 类名（如 `bi-briefcase`），仅展示用 |
| `color` | string | 认证标识配色：`#rgb` / `#rrggbb` / `#rrggbbaa`；空表示前端按内置兜底色 |
| `intro` | string | 一句话简介，选类型时的副文案 |
| `notice` | string | 认证说明，**后台填写**，申请页原样展示给用户 |
| `categories` | json 数组 | 该类型下的认证领域候选，顺序即展示顺序 |
| `fields` | json 数组 | 申请字段定义，见下节 |
| `conditions` | json 对象 | 申请条件（粉丝 / 文章 / 动态 / 注册天数），见「申请条件说明」 |
| `sort` | int | 排序，小的在前；同值时按 `id` 升序 |
| `enable` | int | `1` 启用 / `0` 停用；停用后前台不再可选，已有记录照常展示 |
| `create_time` / `update_time` | int | 秒级时间戳 |

### 字段定义说明

`fields` 是 `[]CertField`，每项支持以下键：

| 键 | 类型 | 说明 |
| :--- | :--- | :--- |
| `key` | string | 存储键，同类型内唯一；`title` / `category` / `images` 为内置键 |
| `label` | string | 展示名称，为空时回落为 `key` |
| `type` | string | 字段类型，见下表 |
| `required` | bool | 是否必填，后端提交时按此校验 |
| `placeholder` | string | 输入框占位文案 |
| `hint` | string | 字段下方说明 |
| `max` | int | 最大字符数，`0` 表示按类型默认（单行 64 / 多行 500 / 链接 512） |
| `options` | json 数组 | `select` 的候选值；为空且 `key=category` 时自动使用类型的认证领域 |
| `multiple` | bool | `select` 是否多选 |
| `max_count` | int | `image` 最多几张，`0` 表示 6，上限 12 |
| `public` | bool | 是否公开展示（通过后他人可在主页看到该项） |
| `admin_only` | bool | 仅后台可见（如联系方式），优先级高于 `public` |

字段类型（`type`）取值：

| 值 | 说明 | 提交格式 |
| :--- | :--- | :--- |
| `text` | 单行文本 | string |
| `textarea` | 多行文本 | string |
| `number` | 数字 | number |
| `select` | 下拉选择 | string；`multiple=true` 时为 string 数组 |
| `date` | 日期 | string，`YYYY-MM-DD` |
| `link` | 链接 | string，必须以 `http://` / `https://` 开头 |
| `image` | 图片 | string 数组（URL），也接受逗号串 |

### 申请条件说明

`conditions` 是**申请门槛**：未达标的用户在前台不能提交，并会看到「还差多少」。四项全部为 `0` 表示无门槛。

| 键 | 类型 | 统计口径 | 单位 |
| :--- | :--- | :--- | :--- |
| `fans` | int | 粉丝数：`inis_user_follows` 中 `follow_uid=该用户` 且 `status=1` 的记录数 | 人 |
| `articles` | int | 已发布文章数：`uid=该用户` 且 `audit=1` 且 `status=1` | 篇 |
| `moments` | int | 已发布动态数：同文章口径 | 条 |
| `days` | int | 注册天数：`users.create_time` 到当前的自然天数（不足一天按 0 计） | 天 |

```json
{
  "fans": 100,
  "articles": 10,
  "moments": 0,
  "days": 30
}
```

判定口径：

- 负数按 `0` 处理，单项上限 `1e8`（防止手滑填出永远无法达成的数字）；
- **只统计已发布内容**（`audit=1` 且 `status=1`），草稿与待审稿不计入，避免靠刷数量过门槛；
- 申请页与提交接口读的是同一份统计（`model.CertUserStats`），不会出现「页面显示达标、提交被拒」；
- 统计结果**缓存 3 分钟**（`cert-user-stats-{代际}-{uid}`）；关注 / 取关、文章与动态的发布 / 删除 / 审核、认证类型配置改动都会推进「代际」使缓存整体失效，正常操作后不会看到过期数字；
- 未登录访问 `enable` 时不做判定（`met=true`、`stats={}`），把「未登录」留给申请接口的 401 处理，避免误导成「条件不达标」。

### 内置字段键

以下三个键有特殊语义，值会额外写回认证记录的独立列：

| key | 写入列 | 说明 |
| :--- | :--- | :--- |
| `title` | `title` | 认证名称，展示在主页昵称旁；为空时回落为类型名 |
| `category` | `category` | 认证领域，后台可按它筛选 |
| `images` | `images` | 证明材料，以逗号分隔存库，后台审核时查看 |

其它键的值统一存入记录的 `data` 列（JSON）。

### 权限说明

- `enable` 为公开接口：申请页在未登录时也要能渲染表单；
- 其余接口在权限规则里为 `type=login`（登录即可通过中间件），再由控制器 `meta.permit` 判定权限点，未授予返回 `403`。

## 状态码规范

| 状态码 | 说明 | 使用场景 |
| :--- | :--- | :--- |
| 200 | 请求成功 | 查询、创建、更新、删除成功（业务码在 body 的 `code`） |
| 400 | 请求错误 | 参数校验失败、类型下仍有记录且未带 `force` |
| 401 | 未授权 | 未登录（后台接口） |
| 403 | 禁止访问 | 已登录但未授予该权限点 |
| 404 | 资源不存在 | 待修改的类型不存在 |
| 405 | 方法不允许 | 方法名不存在 |

- **请求方式**: `GET`
- **请求地址**: `/api/cert-type/enable`

### 2. 认证类型列表（后台） [all]

- **接口类型**: 业务接口
- **请求方式**: `GET`
- **请求地址**: `/api/cert-type/all`
- **权限**: 登录 + 权限点（`meta.permit`，未授予返回 403）
- **说明**: 后台类型列表，含已停用的类型，并附带每个类型下的认证记录数

**请求参数**:

| 参数名 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| `page` | int | 否 | 页码，默认 1，`<=0` 按 1 处理 |
| `limit` | int | 否 | 每页条数，默认 100，上限 200 |

**成功响应** (200):

```json
{
  "code": 200,
  "msg": "查询成功！",
  "data": {
    "data": [
      {
        "id": 1,
        "name": "职业认证",
        "notice": "……",
        "categories": ["编程开发"],
        "fields": [],
        "sort": 1,
        "enable": 1,
        "used": 12
      }
    ],
    "count": 3,
    "page": 1
  }
}
```

**响应字段说明**:

| 字段 | 说明 |
| :--- | :--- |
| `used` | 该类型下的认证记录数（删除保护的依据） |
| `page` | 总页数 `ceil(count/limit)` |

**错误响应**:

| code | msg | 触发条件 |
| :--- | :--- | :--- |
| 403 | `无权限：当前账号未被授予该权限点！` | 未授予权限点 |

### 3. 新建认证类型 [create]

- **接口类型**: 业务接口
- **请求方式**: `POST`
- **请求地址**: `/api/cert-type/create`
- **权限**: 登录 + 权限点（`meta.permit`，未授予返回 403）
- **说明**: 新建一个类型，新建后 `id` 即为该类型认证记录的 `cert_type`

**请求参数**:

| 参数名 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| `name` | string | **是** | 类型名称，超过 32 字符截断 |
| `icon` | string | 否 | Bootstrap Icons 类名 |
| `color` | string | 否 | 标识配色，非法值按空处理（走内置兜底色） |
| `intro` | string | 否 | 一句话简介 |
| `notice` | string | 否 | 认证说明，超过 2000 字符截断 |
| `categories` | json 数组 或 逗号串 | 否 | 认证领域，去空去重；不传为 `[]` |
| `fields` | json 数组 | **是** | 申请字段定义，**至少 1 个** |
| `conditions` | json 对象 | 否 | 申请条件，不传按全部 `0`（无门槛） |
| `sort` | int | 否 | 排序，默认 0 |
| `enable` | int | 否 | 默认 1（启用） |

**成功响应** (200):

```json
{
  "code": 200,
  "msg": "创建成功！",
  "data": {
    "id": 4
  }
}
```

**错误响应**:

| code | msg | 触发条件 |
| :--- | :--- | :--- |
| 403 | `无权限：当前账号未被授予该权限点！` | 未授予权限点 |
| 400 | `请填写认证类型名称！` | `name` 为空 |
| 400 | `至少配置一个需要用户填写的字段！` | `fields` 缺失或清洗后为空 |

### 4. 修改认证类型 [update]

- **接口类型**: 业务接口
- **请求方式**: `PUT`
- **请求地址**: `/api/cert-type/update`
- **权限**: 登录 + 权限点（`meta.permit`，未授予返回 403）
- **说明**: 修改类型；**局部更新**，未传的键沿用原值（只改启停时只需传 `id` + `enable`）

**请求参数**:

| 参数名 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| `id` | int | **是** | 类型 ID；`<=0` 返回 400 |
| `name` | string | 否 | 不传或空串时沿用原值 |
| `icon` | string | 否 | 不传或空串时沿用原值 |
| `color` | string | 否 | 不传沿用原值；**传空串表示恢复默认色** |
| `intro` | string | 否 | 不传或空串时沿用原值 |
| `notice` | string | 否 | 不传或空串时沿用原值 |
| `categories` | json 数组 或 逗号串 | 否 | 传 `[]` 表示清空 |
| `fields` | json 数组 | 否 | 传了就必须至少 1 个 |
| `conditions` | json 对象 | 否 | 不传沿用原值；传 `{"fans":0,...}` 表示取消门槛 |
| `sort` | int | 否 | 不传沿用原值，传 `0` 生效 |
| `enable` | int | 否 | 不传沿用原值，传 `0` 生效（停用） |

**成功响应** (200):

```json
{
  "code": 200,
  "msg": "更新成功！",
  "data": {
    "id": 1
  }
}
```

**错误响应**:

| code | msg | 触发条件 |
| :--- | :--- | :--- |
| 403 | `无权限：当前账号未被授予该权限点！` | 未授予权限点 |
| 400 | `id 不能为空！` | `id <= 0` |
| 404 | `认证类型不存在！` | 类型不存在或已删除 |
| 400 | `请填写认证类型名称！` | 改完后名称为空（如显式传了空串且原值也为空） |
| 400 | `至少配置一个需要用户填写的字段！` | `fields` 传了但清洗后为空 |

### 5. 删除认证类型 [remove]

- **接口类型**: 业务接口
- **请求方式**: `DELETE`
- **请求地址**: `/api/cert-type/remove`
- **权限**: 登录 + 权限点（`meta.permit`，未授予返回 403）
- **说明**: 软删除类型；类型下仍有认证记录时**必须显式带 `force=1`**，否则拒绝

**请求参数**:

| 参数名 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| `ids` | int / 逗号串 / 数组 | **是** | 要删除的类型 ID |
| `force` | bool / int | 否 | `1` / `true` 表示已知历史记录会变成「未知类型」，强制删除 |

**成功响应** (200):

```json
{
  "code": 200,
  "msg": "删除成功！",
  "data": {
    "ids": [4]
  }
}
```

**错误响应**:

| code | msg | 触发条件 |
| :--- | :--- | :--- |
| 403 | `无权限：当前账号未被授予该权限点！` | 未授予权限点 |
| 400 | `ids 不能为空！` | 未传或解析不出 ID |
| 400 | `该类型下还有 12 条认证记录，删除后这些记录将显示「未知类型」；确认删除请带 force=1` | 类型下仍有记录且未带 `force` |
| 400 | `删除失败！` | 写库失败 |

---

## 特殊说明

1. **删除是软删除**（`delete_time`），且默认有删除保护：类型被删后历史认证记录的 `cert_type` 仍指向原 `id`，类型文案回退到内置枚举，最终落到「未知类型」；
2. **`fields` / `categories` 存 JSON 文本**，读取时清洗：非法 `type` 回落 `text`、重复 `key` 只保留第一个、空 `key` 丢弃，因此脏配置不会让接口整体报错；
3. **`category` 字段的选项联动**：配置了 `options` 就用配置值，留空则自动使用本类型的 `categories`，改领域不必回头同步字段；
   `categories` 仅用于「申请页下拉 + 后台筛选」，**不在个人主页展示**（主页认证区默认只显示认证名称与认证说明）；
4. **首次安装自动播种**职业认证 / 兴趣认证 / 机构认证三条（`id` 为 1 / 2 / 3），与升级前的内置枚举一致，老数据无需迁移；
5. **类型停用不等于删除**：停用后前台申请页不再出现该类型，但已提交的认证记录照常展示与审核；
6. 前台申请页在类型全部停用时展示「站点暂未开放认证申请」，不渲染空表单；
7. **申请条件是硬门槛**：`apply` 按 `conditions` 校验，未达标直接返回 400（文案带门槛与当前值），前台也会禁用提交按钮；后台改资料（`edit`）不受门槛限制，运营改老用户资料不会被拦住；
8. **标识颜色只接受十六进制**（`#rgb` / `#rrggbb` / `#rrggbbaa`），非法值按空处理。颜色会直接写进前端样式，放开任意字符串等于留一个 CSS 注入点；
9. **配色全站同源**：昵称旁的盾牌、简介下的认证行、本人「我的认证」页都读 `cert-type` 的 `color`；为空时前端按内置兜底（职业金 / 兴趣蓝 / 机构绿 / 其它品牌蓝），不会再出现同一认证两种颜色。
