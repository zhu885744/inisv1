## 一、系统概览

### 1.1 技术栈

| 项目 | 说明 |
|---|---|
| 语言 / 框架 | Go + Gin |
| ORM | Gorm（参数化查询，软删除走 `soft_delete`） |
| 数据库 | MySQL（`config/database.toml`） |
| 缓存 | Redis / File / Ram / BigCache 四驱动（`config/cache.toml`） |
| 存储 | 本地 `local` / 腾讯云 `cos`（`config/storage.toml`） |
| 实时通信 | 自研 WebSocket Hub，支持多实例 Redis 集群广播（`app/socket`） |
| 定时任务 | gocron（`app/timer`） |
| 前端 | Vue（Mellow 后台 + 主题），可内嵌进二进制单文件部署 |

### 1.2 路由体系

系统有四套路由，互不干扰：

| 路由组 | 前缀 | 入口文件 | 用途 |
|---|---|---|---|
| API | `/api/{controller}/{method}` | `app/api/route/app.go` | 业务接口，57 个控制器 |
| 开发/运维 | `/dev/{controller}/{method}` | `app/dev/route/app.go` | 安装引导、主机信息 |
| 首页 | `/`、`/api/template-status` | `app/index/route/app.go` | 主题渲染、模板就绪探测 |
| WebSocket | `/socket` | `app/socket/route/app.go` | 实时通信 |

所有控制器都按资源路由注册五种形态：`ANY /api/{c}`（INDEX）、`GET|PUT|POST|DELETE /api/{c}/:method`。

方法名在控制器内部通过 `allow` 白名单映射到具体函数，未登记的方法统一返回 405「方法调用错误」。

### 1.3 请求处理链（`/api` 分组中间件顺序）

```
IpBlack → QpsPoint → QpsGlobal → Params → Auth → Rule → ApiKey → Restriction → CaptchaGuard
```

| 中间件 | 作用 |
|---|---|
| `IpBlack` | IP 黑名单拦截（进程内快照，零查库） |
| `QpsPoint` / `QpsGlobal` | 单接口 / 全站 QPS 限流，超阈值可自动封禁 |
| `Params` | 统一解析 query / form / JSON body 到 `params` |
| `Auth` | 会话鉴权，解析登录用户与后台管理会话 |
| `Rule` | 权限规则校验（common / login / default / admin 四类） |
| `ApiKey` | 接口密钥校验（可放行本站同源 / 内网） |
| `Restriction` | 封禁限制位校验（禁言 / 禁评论 / 禁上传 / 禁互动） |
| `CaptchaGuard` | 滑块验证（验证码防刷 + 敏感操作二次校验） |

其他全局中间件：`Cors`、`Install`（未安装时引导）、`Tls`、`LocalOnly`、`FileSizeLimit`、日志与脱敏。

### 1.4 鉴权与权限模型

| 概念 | 说明 |
|---|---|
| 会话 | 服务端会话（Cookie / `Authorization`），JWT 已移除 |
| 后台会话 | `comm/admin-login` 二次密码验证后签发，独立 cookie，只影响后台 |
| 权限规则 `auth_rules` | 每条路由一行（method + route），`type` 四档：`common` 公开、`login` 需登录、`default` 需权限点、`admin` 需后台会话 |
| 权限分组 `auth_group` | 分组持有权限点集合，`root=1` 表示越权分组（含 `all`） |
| 后台页面 `auth_pages` | 后台菜单 / 页面级权限树 |
| 兜底 | 未登记路由按「需权限点」处理；启动时由 `EnsureAuthRules` 自动补齐新增接口 |
| 封禁限制位 | `users.restrictions` 位掩码，支持禁言 / 禁评论 / 禁上传 / 禁互动等分项限制 |

### 1.5 通用接口约定

所有控制器共享一套标准 CRUD 方法（下文模块表里简写为「标准 CRUD」）：

| 方法 | 动词 | 语义 |
|---|---|---|
| `one` | GET | 按 id 取单条（支持 `field` 指定字段） |
| `all` | GET | 分页列表，支持 `page` / `limit`（上限 200）/ `order` / `where` / `like` / `withTrashed` |
| `sum` `min` `max` `rand` `count` `column` | GET | 聚合查询 |
| `save` | POST | 有 `id` 走更新、无 `id` 走创建（upsert） |
| `create` | POST | 新建 |
| `update` | PUT | 按 id 更新 |
| `restore` | PUT | 从回收站恢复 |
| `remove` | DELETE | 软删除（进回收站） |
| `delete` | DELETE | 物理删除（需 `withTrashed` 定位） |
| `clear` | DELETE | 清空回收站 |

统一的查询参数：`where` / `or` / `like` / `not` / `null` / `notNull` 支持 JSON 或者数组写法；`cache=false` 可关闭接口级缓存。

统一响应：`{ code, msg, data }`，`code` 沿用 200 / 204 / 400 / 401 / 403 / 405 / 500。

## 十、WebSocket 实时能力

- 连接：`GET /socket`（支持 `?token=` 连接后 `{type:"auth"}` 升级身份，跨域场景用）
- 客户端 → 服务端事件：

| type | 说明 |
|---|---|
| `auth` | 连接后鉴权升级身份 |
| `ping` | 心跳（回 `pong`） |
| `ack` | 批量送达确认（`target_uid` + `seq`） |
| `read` | 已读水位上报 |
| `typing` | 正在输入（私聊 / 群聊） |
| `private` | 私信（落库后转发，与 HTTP 发送共用同一模型） |
| `single` / `notification` | 定向消息 / 通知 |
| `broadcast`（或不带 type） | 全站广播（仅管理员） |
| `kick` | 踢下线（仅管理员） |

- 服务端 → 客户端事件：`connect`、`pong`、`error`、`status`（仅管理员，CPU / 内存 / 在线数）、`kicked`、`private`、`single`、`notification`、`broadcast`、`room_*`（`room_message` / `room_revoke` / `room_delete` / `room_typing` / `room_mute` 等）、`chat_typing`、`chat_mention`、`chat_revoke`、`chat_read`、`chat_delete`
