# inis CMS 代码优化清单

> 本文档为全局代码审查结果的可追踪清单，配合《项目优化规划.md》使用。
> 每条问题标注：**编号 / 严重程度 / 文件 / 位置 / 问题描述 / 优化建议**。
> 严重程度：🔴 高（必须处理）｜🟠 中（应尽快处理）｜🟡 低（择机处理）。

---

## 一、安全问题（P0）

### 🔴 S-1 硬编码服务密钥
- **文件**：`app/facade/const.go`（第 9 行）
- **问题**：`Token = "(unti.io)"` 硬编码，作为设备签名盐值（`comm.go` 中 `utils.Hash.Token`）。攻击者可逆向伪造上报签名。
- **建议**：迁移到配置文件，支持环境变量覆盖；盐值不再写死。

### 🔴 S-2 SQL 拼接注入（ILike）
- **文件**：`app/facade/mysql.go`（第 571 行 `ILike`）
- **问题**：`sql += fmt.Sprintf("`%v` LIKE '%v' OR ", item[0], value)` 将字段名与用户输入直接拼进 SQL，未参数绑定，存在 SQL 注入。
- **建议**：字段名走白名单校验，值改用 GORM 参数占位 `?`。

### 🔴 S-3 SQL 拼接注入（Where/WhereIn/Not/Or）
- **文件**：`app/facade/mysql.go`（第 115/120/142 行等）
- **问题**：字段名 `args[0]`、操作符 `args[1]` 通过 `fmt.Sprintf` 拼接，若来自 `IWhere` 解析的 JSON key 可注入。
- **建议**：字段名/操作符白名单，值参数化。

### 🔴 S-4 SQL 拼接注入（聚合字段）
- **文件**：`app/facade/mysql.go`（第 965/977/989 行 `Sum`/`Max`/`Min`）
- **问题**：`"sum(" + cast.ToString(field) + ")"` 字段名直接拼接未校验。
- **建议**：字段名校验后再拼接。

### 🔴 S-5 路径遍历（静态文件读取）
- **文件**：`config/app.go`（第 127-145 行 `notRoute`）
- **问题**：`"public" + path` 直接读文件，未做 `filepath.Clean` 与目录边界校验，`../../` 可读任意文件；同时 `strings.LastIndex` 返回 -1 时切片存在 panic 隐患。
- **建议**：路径规范化 + 前缀白名单校验 + 越界保护。

### 🔴 S-6 路径遍历（存储删除）
- **文件**：`app/facade/storage.go`（第 313-319 行 `Delete`）
- **问题**：本地删除直接 `os.Remove(path)`，`TrimPrefix` 无法阻止 `../../`，可删任意文件。
- **建议**：`filepath.Clean` 后校验路径必须落在存储根目录内。

### 🔴 S-7 密钥文件权限过宽
- **文件**：`app/facade/crypt.go`（第 54 行）
- **问题**：`os.WriteFile(..., 0755)` 写入 JWT 密钥文件，其他用户可读。
- **建议**：改为 `0600`。

### 🔴 S-8 JWT 密钥生成强度不足
- **文件**：`app/facade/crypt.go`（第 44-45 行）
- **问题**：`md5(uuid + unix 时间戳)` 派生密钥，时间戳可推测，MD5 强度不足。
- **建议**：`crypto/rand` 生成随机字节。

### 🔴 S-9 密钥日志泄露
- **文件**：`app/facade/crypt.go`（第 107-110 行 `initCrypt`）
- **问题**：热更新日志打印 `jwt.key` 明文。
- **建议**：移除明文输出，仅记录是否变更。

### 🔴 S-10 硬编码明文 Token + 非恒定时间比较
- **文件**：`app/middleware/token.go`（第 11 行 `defaultTokenValue = "0147."`）
- **问题**：硬编码明文 Token，比较用 `!=`（非恒定时间）。
- **建议**：改为配置项，比较改用 `subtle.ConstantTimeCompare`。

### 🟠 S-11 密码哈希算法需审计
- **文件**：`app/socket/controller/index.go`（第 266 行）、全局 `utils.Hash`
- **问题**：密码哈希为自定义 `utils.Hash.Sum32`，未见加盐/迭代证据，存在彩虹表风险。
- **建议**：审计 `go-utils` 的 Hash 实现，必要时平滑迁移至 bcrypt/argon2。

### 🟠 S-12 前端签名逻辑可预测
- **文件**：`app/facade/comm.go`（第 105-107 行 `Signature`）
- **问题**：AES key/iv 使用固定盐（`"AesKey"`/`"AesIv"`），gorgon 前缀硬编码 `"8642"`，无实际防伪能力。
- **建议**：若需真实防伪，改为服务端下发随机密钥。

## 二、事务与并发问题（P1）

### 🔴 C-1 封禁删除内容脱离事务
- **文件**：`app/api/controller/users.go`（`ban`，第 1388-1399 行）
- **问题**：删除文章/动态/评论/点赞/收藏在 `go func(){}` 异步执行，事务已提交才执行，失败无感知。
- **建议**：移入事务或同步执行并检查错误。

### 🔴 C-2 注销 Destroy 使用裸 goroutine
- **文件**：`app/model/users.go`（`Destroy`，第 351-371 行）
- **问题**：各表删除均 `go ...Delete()`，未等待、未查错、无 recover。
- **建议**：同步执行 + 事务 + 错误上抛。

### 🔴 C-3 AfterSave 异步更新 avatar 竞态
- **文件**：`app/model/users.go`（`AfterSave`，第 112-117 行）
- **问题**：`go func(){ tx.Model(this).UpdateColumn(...) }()` 复用事务 `tx`（可能已提交），且修改 `this.Avatar` 存在数据竞争。
- **建议**：改为同步处理头像域名替换。

### 🟠 C-4 经验值发放非原子
- **文件**：`app/model/exp.go`（`Add`，第 323-331 行）
- **问题**：流水 `Create` 成功后 `Inc("exp")` 自增，两步无事务，`Inc` 的 error 被忽略。
- **建议**：事务包裹，或原子 SQL 一并更新。

### 🟠 C-5 频控计数读-改-写竞态
- **文件**：`app/api/controller/users.go`（`email`/`phone`/`appealPublic` 等多处）
- **问题**：`go facade.Cache.Set(..., dailyCount+1, ...)` 基于本地变量 +1 异步写回，高并发下计数覆盖，频控失效。
- **建议**：Redis INCR / DB 原子自增。

### 🟠 C-6 邮件通知 goroutine 长时间 Sleep
- **文件**：`app/api/controller/comment.go`（第 661-703 行）
- **问题**：goroutine 内按分钟级 `time.Sleep` 重试发信，无超时/取消，易 goroutine 堆积。
- **建议**：有限重试 + 超时，或消息队列。

## 三、错误处理问题（P1）

### 🟠 E-1 大量 error 被忽略
- **文件**：`app/api/controller/comment.go`（`replies`）、`article.go`（`updateViews` 第 713 行）等全局
- **问题**：`_, err :=` / 直接丢弃返回值的现象普遍，浏览量、经验值更新失败静默。
- **建议**：至少记录日志，关键路径上抛。

### 🟠 E-2 查询失败与无数据语义混淆
- **文件**：各 controller 中 `item, _ := ...Find()`、`count, _ := ...Count()` 等
- **问题**：数据库错误被当作空结果，返回「无数据」而非错误，掩盖故障，且权限判断依赖空值可能误判。
- **建议**：区分 error 与空结果。

### 🟠 E-3 Exist 忽略 error 绕过唯一性校验
- **文件**：`app/model/users.go`（`AfterSave`，第 119-138 行）
- **问题**：`exist, _ := ...Exist()` 查询出错时 `exist=false`，绕过账号/邮箱/手机号唯一性校验。
- **建议**：检查 error，出错时中断保存。

## 四、参数校验问题（P1）

### 🟠 V-1 validator 规则过少
- **文件**：`app/validator/article.go`（仅校验 `top`）、`comment.go`（仅 `pid`/`content`）
- **问题**：`title`/`content`/`status` 等关键字段无规则，靠 controller 手工判断，非法值未拦截。
- **建议**：补齐 validator 规则。

### 🟠 V-2 评论 pid 缺少父评论校验
- **文件**：`app/api/controller/comment.go`（`create`）
- **问题**：未校验父评论是否存在/是否同属 `bind_id`，可乱挂回复层级。
- **建议**：校验 pid 有效性。

### 🟠 V-3 注册 password 未判空
- **文件**：`app/api/controller/users.go`（`create`，第 370-400 行）
- **问题**：validator `min=6` 对空串可能不生效，未显式判空，可能写入空密码。
- **建议**：显式非空校验。

### 🟠 V-4 文章更新权限语义混淆
- **文件**：`app/api/controller/article.go`（`update`，第 423-427 行）
- **问题**：`Find` 出错返回 nil 时 `cast.ToInt(nil)=0`，文章不存在也返回 403 而非 404。
- **建议**：区分「不存在」与「无权限」。

## 五、性能问题（P2）

### 🟠 P-1 图片动态处理无缓存
- **文件**：`config/app.go`（`handleImageFile`）
- **问题**：每次请求都 `imaging.Open` 读盘 + 重新裁剪/编码，CPU/IO 浪费。
- **建议**：按 `path+size+mode` 缓存处理结果。

### 🟠 P-2 权限判断实时查库
- **文件**：`app/api/controller/base.go`（`root`，第 227-252 行）
- **问题**：`meta.root` 每次调用实时查 `AuthGroup`，高频接口反复触发 DB 查询。
- **建议**：缓存 + 变更失效。

### 🟠 P-3 索引落地确认
- **文件**：见 `docs/database-index.md`
- **问题**：文档给出了索引建议，需确认 `inis_*` 核心表索引已创建。
- **建议**：核对并补建缺失索引。

### 🟠 P-4 缓存键前缀不统一
- **文件**：`app/api/controller/article.go`（第 718 行）vs `base.go`（第 266 行）
- **问题**：有的带 `[GET]` 有的不带，命名不一致，可能导致缓存清理遗漏。
- **建议**：统一前缀规范。

### 🟠 P-5 低效 LIKE 前缀查询
- **文件**：`app/model/users.go`（`Rules`，第 151 行）、`base.go` `root`
- **问题**：`Like("uids", "%|uid|%")` 无法走索引，权限相关查询频繁且低效。
- **建议**：评估改为关联表或规范化存储。

## 六、代码质量与重复代码（P3）

### 🟠 D-1 三控制器大量重复样板
- **文件**：`article.go` / `comment.go` / `users.go`
- **问题**：`buildQuery`、`withTrashOptions`、`getFromCache`、`setCache`、`count`/`sum`/`min`/`max`/`column`、`remove`/`delete`/`clear`/`restore`/`save` 等几乎逐字重复。
- **建议**：抽取公共基类或泛型 helper。

### 🟠 D-2 脱敏逻辑重复
- **文件**：`users.go`（`one`/`all`）、`comment.go`（`maskItem`）
- **问题**：邮箱/手机/账号脱敏实现多份。
- **建议**：提取统一脱敏函数。

### 🟠 D-3 发码逻辑重复
- **文件**：`users.go`（`email`/`phone`/`destroy`/`appealPublic`）
- **问题**：「频控检查 → 发码 → 缓存验证码」逻辑重复 4 处。
- **建议**：提取统一发码 helper。

### 🟠 D-4 大量 any/interface{} + 反射
- **文件**：`app/api/controller/base.go`（`call` 反射调用、`allow map[string]any`）、所有 model 的 `Json/Text/Result any` 字段
- **问题**：丧失编译期类型检查，方法名拼写错误只能运行时发现；`Result` 声明为 `any` 却存 `varchar(256)`。
- **建议**：逐步强类型化。

### 🟠 D-5 超长 controller 文件
- **文件**：`users.go`（2040 行）、`comment.go`（1157 行）
- **问题**：controller 同时承担参数校验/权限/业务/缓存/审计/脱敏多重职责。
- **建议**：按职责拆分，下沉到 service 层。

### 🟠 D-6 死代码未清理
- **文件**：`app/model/comment.go`（`author`/`article`/`page` 旧方法）、`app/api/middleware/ip-black.go`（`getBlacklist`/`IsIpBanned` 未被复用）
- **建议**：删除无引用代码。

### 🟠 D-7 调试输出残留
- **文件**：`app/api/controller/test.go`（第 178-210 行）、`OAuth.go`（第 94/155 行）、`socket/controller/serialize.go`（第 248 行）、`facade/sms.go`（多处 `fmt.Printf`）
- **建议**：统一走 `facade.Log`，移除临时打印。

## 七、工程与规范问题（P3）

### 🟡 R-1 配置热更新被阻塞
- **文件**：`main.go`（`watch` 第 34-42 行 + `run` 第 113 行）
- **问题**：`OnConfigChange` 内递归 `watch()` + `run()`，而 `run()` 含 `select{}` 永久阻塞，热更新链路异常，且可能重复注册监听、goroutine 泄漏。
- **建议**：重构为「停止旧 Server → 重建 → 重新 Listen」的清晰流程，避免递归与阻塞。

### 🟡 R-2 路由注册顺序不确定
- **文件**：`app/api/route/app.go`（第 65-73 行）
- **问题**：`for key, item := range controllers` 遍历 map 注册，顺序随机，不利于调试与文档确定性。
- **建议**：改用有序 slice 注册。

### 🟡 R-3 命名不一致
- **文件**：`app/api/middleware/`（`getUserFromCtx` vs `getUserFromContext`）
- **问题**：两个几乎相同实现的函数命名不同。
- **建议**：统一命名，复用同一函数。

### 🟡 R-4 注释错别字
- **文件**：`app/api/controller/users.go`（第 931/1029 行）
- **问题**：「未了防止」应为「为了」。
- **建议**：修正。

### 🟡 R-5 结构体注释风格混杂
- **文件**：`app/model/users.go`（第 17 行等）
- **问题**：comment 标签内分号位置不统一。
- **建议**：统一风格。

### 🟡 R-6 类型断言缺保护
- **文件**：`app/api/controller/base.go`（第 111 行 `header`）
- **问题**：`result = def[0].(string)` 未做安全断言，非 string 默认值会 panic。
- **建议**：使用 `cast.ToString` 或双值断言。

## 九、建议处理顺序

1. **第一批（安全）**：S-2/S-3/S-4（SQL 注入）→ S-5/S-6（路径遍历）→ S-1/S-7/S-8/S-9/S-10（密钥治理）→ S-11（密码哈希审计）。
2. **第二批（正确性）**：C-1/C-2/C-3（事务竞态）→ C-4/C-5（原子性）→ E-1/E-2/E-3（错误处理）→ V-1~V-4（校验）。
3. **第三批（性能）**：P-1/P-2/P-4（缓存）→ P-3/P-5（索引与查询）。
4. **第四批（质量）**：D-1~D-7（去重、死代码、规范）→ R-1~R-6（工程治理）。
