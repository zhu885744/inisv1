# 接口文档撰写规范

`docs/API docs` 下所有接口文档必须遵循本规范。新增文档、修改文档时先对照本页，不合规的按「改造清单」逐项对齐。

---

## 一、文件与标题

| 项 | 规则 |
| :--- | :--- |
| 文件名 | 全小写、中划线分词，取控制器名：`api-keys.md`、`user-follows.md`、`links-group.md` |
| 一级标题 | 文件首行**有且只有一个** `#`，格式为「功能名 + 空格 + 接口文档」：`# 文章管理 接口文档` |
| 标题层级 | `#` 文档标题 → `##` 章节 → `###` 单个接口；**不使用 `####` 及更深层级** |
| 空行 | 标题前后各一个空行；表格、代码块前后各一个空行 |

---

## 二、章节骨架

顺序固定，不得调换、不得改名：

```markdown
# XXX 接口文档

## 接口概述

## 状态码规范

## 接口列表

## 特殊说明
```

| 章节 | 必填 | 内容 |
| :--- | :--- | :--- |
| `## 接口概述` | 是 | 控制器职责一句话；通用约定（鉴权、软删除、分页）放这里 |
| `## 状态码规范` | 是 | 只列本文档接口会返回的状态码，用统一表格（见第四节） |
| `## 接口列表` | 是 | 每个接口一个 `###`，格式见第三节 |
| `## 特殊说明` | 是 | 注意事项、缓存策略、数据表、相关文档链接；没有内容时写「无」 |

### 例外：指南与能力说明

以下三类文档不按「一个接口一个小节」组织，允许自定义 `##` 章节，但必须满足：唯一 `#` 标题、
有 `## 接口概述`、无 `####` 及更深层级、表格与代码块规则一致。

| 文档 | 说明 |
| :--- | :--- |
| `content-scope.md` | 能力说明（可见范围判定），接口明细在 `unlock.md`，可省略 `## 状态码规范` |
| `user-interaction-guide.md` | 跨模块聚合指南，按业务模块分节 |
| `base.md` | 内部基类，无 HTTP 接口；`## 接口列表` 收录可继承的 Go 方法，方法名用加粗标签 |

### 概述内的补充说明

字段语义、枚举、配置项、数据表等**说明性内容**，一律作为 `## 接口概述` 下的 `###` 子节，不要单独提到 `##` 层级。子节按「先字段、再行为」排列，常用名称：

- `### 字段说明`（表字段语义）
- `### 接口类型说明`（基础接口 / 特殊接口支持哪些 action）
- `### 权限说明`
- `### 配置项`（如 `SYSTEM_EXP_RULES`）

> 只有「单个接口的专属说明」才写在 `### 接口列表` 内对应接口下。

### 接口一览表

接口数量不多、但需要一张总表便于查阅时，可在 `## 接口概述` 末尾加 `### 接口一览`，
表头固定为 `方法 | 路径 | 权限 | 说明`；正文仍按第三节逐接口展开，不以后者替代前者。

### 特殊说明内的子节

`## 特殊说明` 下的子节用 `### 1. xxx` / `### 2. xxx` 编号；跨文档引用统一放 `### 相关文档`，
写相对链接即可（`[内容可见范围 接口文档](./content-scope.md)`）。

## 三、接口条目格式

每个接口一个 `###`，编号在 `## 接口列表` 内连续递增，标题格式：

```markdown
### 1. 获取单个密钥 [one]

- **接口类型**: 获取指定
- **请求方式**: `GET`
- **请求地址**: `/api/api-keys/one`
- **说明**: 根据条件获取单个密钥

**请求参数**:

| 参数名 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| `id` | int | 否 | 密钥 ID |

**响应示例**:

```json
{
  "code": 200,
  "msg": "数据请求成功！",
  "data": {}
}
```
```

硬性规则：

1. **不按 HTTP 方法分组**。不要写 `### 1. GET 请求接口` 这类分组标题，每个接口直接占一个 `###`。
2. 标题方括号里写 **action 名**（路由末段），与「请求地址」最后一段保持一致。
3. 元信息**必须是列表**（`- **标签**: 值`），不允许写成裸粗体段落（`**请求方式**: \`GET\``）。
4. 标签顺序固定：`接口类型` → `请求方式` → `请求地址` → `权限` → `说明`；`接口类型`、`权限`、`说明` 可省略，其余必填。
   `请求方式` 的值必须用反引号包裹。
5. 参数表表头固定为 `参数名 | 类型 | 必填 | 说明`；字段名用反引号包裹。
6. 响应示例必须用 ` ```json ` 代码块，且保持 `code / msg / data` 三段结构。
7. 接口之间用 `---` 分隔；`##` 章节之间也用 `---` 分隔，`###` 之间不加分隔线。

### 块标签

接口小节内引导表格 / 代码块的粗体标签固定为下表中的写法（半角冒号）：

| 标签 | 用途 |
| :--- | :--- |
| `**请求参数**:` | 参数表 |
| `**成功响应** (200):` | 成功响应示例，括号内为状态码，可省略 |
| `**失败响应** (400):` | 失败响应示例 |
| `**响应字段**:` | 返回字段说明表 |
| `**请求示例**:` | curl / 代码调用示例 |

说明性段落不要用粗体标签（如 `**注意**：`），直接写成正文或引用块。

### 接口较多时

接口超过 20 个、且彼此结构一致时（如 `docs.md`），允许用接口清单表代替逐接口小节：

```markdown
| 方法 | 路径 | 权限 | 说明 |
| :--- | :--- | :--- | :--- |
| GET | `/api/docs/one` | 公开 | 文档详情 |
```

### 无参数的接口

省略参数表，只保留元信息与响应示例；`请求参数` 写「无」：

```markdown
### 2. 退出登录 [logout]

- **请求方式**: `POST`
- **请求地址**: `/api/comm/logout`

**请求参数**: 无
```

## 四、表格

统一写法（左对齐，三格起）：

```markdown
| 状态码 | 说明 | 使用场景 |
| :--- | :--- | :--- |
| 200 | 请求成功 | 查询、操作成功 |
```

- 分隔行固定 `| :--- | :--- |`，不写 `:--`、`---:`。
- 表头不加粗；数据行的状态码、字段名不加粗（字段名用反引号）。
- 状态码表统一表头：`状态码 | 说明 | 使用场景`；不用「含义」。

### 标准状态码表

文档只列实际会返回的行，措辞与下表保持一致：

| 状态码 | 说明 | 使用场景 |
| :--- | :--- | :--- |
| 200 | 请求成功 | 查询、操作成功 |
| 201 | 创建成功 | 新增数据成功 |
| 204 | 无内容 | 查询无数据、无可操作数据 |
| 400 | 请求错误 | 参数校验失败、操作失败 |
| 401 | 未授权 | 未登录或 token 无效 |
| 403 | 禁止访问 | 无操作权限 |
| 405 | 方法不允许 | 请求方法或方法名错误 |
| 500 | 服务器错误 | 服务端内部错误 |

## 五、代码块

- 每个围栏都必须标语言：`json` / `javascript` / `go` / `bash` / `toml` / `http` / `xml` / `text`。
- JSON 示例用 2 空格缩进，键不加引号以外的修饰；不要写 `// 注释`。
- 命令行示例用 `bash`，路径用 `http`。

---

## 六、文字风格

- 用中文全角标点；中英文之间留一个空格（`调用 GET 接口`）。
- 术语首次出现用反引号包裹代码标识：`scope`、`SYSTEM_EXP_RULES`、`/api/article/one`。
- 一段只说一件事；超过 3 行的补充说明改用列表或表格。
- 不使用「我们」「你可以」等口语；直接写「调用方需…」「需传入…」。
- 强调用 `**加粗**`，且只用于真正的风险点（如「**仅超级管理员**」），一段内不超过 2 处。

---

## 七、改造清单（自查用）

新增或改稿后逐条确认：

1. 首行是唯一的 `#` 标题，格式为「功能名 接口文档」
2. 四个 `##` 章节齐全、顺序正确、名称一致
3. 说明性内容都在 `## 接口概述` 的 `###` 子节里，没有游离的 `##`
4. 每个接口一个 `###`，编号连续，无「按方法分组」标题
5. 元信息是列表形式，标签顺序正确，无裸粗体段落
6. 参数表表头为 `参数名 | 类型 | 必填 | 说明`
7. 所有代码块都有语言标注
8. 状态码表用统一表头与措辞
9. 表格分隔行为 `| :--- |`
10. 没有 `####` 及更深层级标题

```markdown

| 400 | 请求错误 | 参数校验失败、操作失败 |
| 401 | 未授权 | 未登录或 token 无效 |
| 403 | 禁止访问 | 无操作权限 |

---

## 接口列表

### 1. 获取单个数据 [one]

- **接口类型**: 获取指定
- **请求方式**: `GET`
- **请求地址**: `/api/xxx/one`

**请求参数**:

| 参数名 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |

**响应示例**:

```json
{
  "code": 200,

  "data": {}
}
```

---

### 2. 保存数据 [save]

- **请求方式**: `POST`

**请求参数**:

| 参数名 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
